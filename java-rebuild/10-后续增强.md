# 10 后续增强（M2，必须晚于M1）

本文件将前面讨论的技术展示方向落实成可执行默认规格，但未声称是当前产品已有功能。先保证完整迁移，新增页面使用功能开关。已有F09的第3／4天提示保持不变。

关于小组统计缓存的业务痛点、技术选择、并发一致性、压测指标及面试表达，见 [Redis 使用方案](11-Redis使用方案.md)。统计缓存已移出 M2，改由 M1 后、M2 前的 B9 批次实施；该方案尚未实施，不代表已取得性能收益。小组实时动态不属 M2，而是 B10，见 [12 实时动态与事件推送](12-实时动态与事件推送.md)；M2 的提醒与周报走 MQ，不复用事件通道。

## X1 Redis打卡榜

当前进行中小组增加次级“打卡榜”入口，不改变小组／记录／数据三项主导航。只按本期有效记录天数排名，日内覆盖不加分，同分并列、加入顺序稳定。结束复盘仍按覆盖率，两个榜的口径必须明确，不能混用。

Redis ZSet按roomId／期次存用户分数，MySQL records为事实。不要消费一条保存消息就盲目ZINCRBY，否则重投会重复；按数据库权威天数写入，结合数据版本防旧消息覆盖。成员注销移除，快照鉴权后读榜，Redis丢失按数据库重建；回源可用、缓存有TTL和数据版本。这里的数据版本复用 B9 的 `rooms.stats_version`，不另建一套。

拟定API：GET /rooms/:id/checkin-ranking → `{items:[{userId,nickname,avatar,days,rank}],dataVersion}`。仅本期有效成员可读。

## X2 用户开启的每日提醒

账号／小组设置增加开关，默认关闭，首期固定北京时间20:00，无需做复杂时间选择。仅针对ACTIVE、当前在组、同意有效、当天无记录者；站内通知明确“今日尚未记录”，不制造健康评价。

Spring Scheduler扫描→MySQL任务及Outbox→RabbitMQ→消费者复核→落库站内通知。开启后不追补过去日期；消费晚于业务日、组结束、已记录、关闭或注销则SKIPPED。开关与旧F09无关。站内通知不是系统推送，只在打开应用可见。

默认任务唯一键：`userId + roomId + businessDate + type`，通知唯一绑定任务ID。Redis只辅助限流，MySQL唯一键防重复。前端可列通知、按本人权限标记阅读，已投递不等于已读。

拟定API：GET/PUT /me/reminder-preference（`{enabled}`）；GET /notifications（游标、每页20条、上限50）；POST /notifications/:id/read。页面只显示用户自己的内容，不把其他成员身体信息塞进提醒。

## X3 本人异步周报

个人分析增加“本周报告”入口；范围为北京时间周一至周日与本期／加入日期的交集，当前周锚点不晚于今天，结束期不晚于endDate。内容为本人记录次数、覆盖率、实际体重趋势和规范变化，首期不放其他成员明细或医学结论；空数据生成明确空态报告。

请求提交返回taskId与状态，后台生成JSON报告，页面轮询查询并显示QUEUED／RUNNING／SUCCEEDED／FAILED，失败提供显式重试。MySQL保存结果，Redis缓存读取；不需要Excel或PDF才能完成本功能。

任务唯一键含本人、room、周起点与数据版本。记录更正后该范围report标过期，新的版本生成新任务，旧任务不能覆盖最新。状态查询／下载均鉴权本人和期次访问，注销立即撤销并清理；执行中定期／落库前复核用户删除状态。

拟定API：POST /rooms/:id/reports/weekly `{weekStart}` → `{taskId,status}`；GET /report-tasks/:id → `{taskId,status,retryable,result?,dataVersion}`；POST /report-tasks/:id/retry（幂等、只有本人失败任务）。范围校验、队列积压和依赖故障可见，不无休止转圈。

## X4 可靠任务基础

- tasks：ID、业务唯一键、类型、用户／组、业务日期／数据版本、状态、attempts、next_run_at、lease_owner／lease_until、最后错误码、结果位置、创建／更新时间。任务的租约token需参与完成写入条件，旧工作者不可覆盖新工作者。
- outbox：eventId、taskId、类型、最小payload、发布状态、尝试次数、下一次时间；任务和Outbox同MySQL事务提交，确认后标已发，断连时重发可能重复。
- RabbitMQ：受控vhost及凭据，持久交换机／队列和消息，发布确认、不可路由返回、处理完成事务提交后手动ACK，prefetch有界。逻辑默认提醒与报告独立队列，失败队列与业务队列分开。
- 单任务首次之外最多3次自动重试，默认间隔10秒／60秒／300秒（可配置），超过后FAILED并进入可见失败清单／死信。实现可用数据库next_run_at补投，避免无限立即requeue；手动重试需本人或受控运维权限并记录审计。
- Redisson按任务类型与扫描时段协调调度，合理超时及释放；扫描崩溃后补扫；不能依靠锁作为“不重复”保证。任务／通知／报告均用业务唯一键兜底。
- 服务重启扫描到期租约恢复，MQ暂停可积压Outbox，恢复补发；消息只放ID／版本，不放验证码、手机号或体重正文。
- 不承诺恰好一次投递，验收至少一次条件下业务结果幂等。任何未来外部短信／邮件发送需单独设计供应商回执与未知结果处理，不能直接复用数据库通知的恰好一次效果宣称。
