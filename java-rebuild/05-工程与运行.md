# 05 工程与运行

## 1. 建议工程布局

```text
apps/java-api/
  pom.xml, mvnw, .mvn/
  src/main/java/.../{identity,room,record,analysis,reminder,support,privacy,common}/
  src/main/resources/{application*.yml,db/migration/}
  src/test/...
apps/web-vue/
  package.json, 锁文件, src/{api,views,components,stores,router,styles}/
deploy/java/
  compose.yml, nginx.conf, 环境示例, Dockerfile或引用路径
scripts/java/
  seed、冒烟、并发、备份、恢复、支持处理等脚本
java-rebuild/
  本需求包、执行状态及后续证据
```

模块内分controller／service／repository／DTO，简单领域逻辑不必过度拆接口。common只放错误、校验、时钟、请求身份等共享基础，不堆所有业务。目标算法和统计为无网络纯逻辑，可注入Clock进行边界测试。数据库连接池、外部HTTP连接与任务线程数有界。

- 锁定Java／Spring Boot／Security／Session／MyBatis-Plus／MySQL／Redis／RabbitMQ／Redisson／Vue／Vant／图表／构建工具兼容版本；记录依据和实际安装输出。不凭模型记忆填写“最新”。
- Maven Wrapper及前端锁文件入库，依赖可重复安装；用稳定维护版本，不沿用截图的版本号。CI与本机Java版本一致。
- 新端口默认前端5173、Java8080、第二实例8081、Nginx入口8088；若占用可改并同步文档，避开现有4180／4181。公网映射另作部署批次。
- 新数据库／Redis namespace／MQ vhost和账号与旧项目隔离；业务库命名shangcheng_java_*、删除清单单独schema。数据库／Redis／MQ管理端口默认仅本机或容器内可达。
- 应用密钥由环境注入，示例只写占位符，忽略实际env与生成数据。日志只含requestId、内部ID、耗时、错误码，不含验证码、会话、完整手机号或身体数值。

## 3. 开发模式与启动交付

提供可复制命令：启动依赖、数据库升级、加载合成数据、启动后端／前端、执行检查与测试、停止和清理仅本项目测试资源。最终也能一条Compose命令启动完整演示。不得在尚未实现时把拟定命令写成已验证。

Java的local/test/sms-trial业务模式与dev/test集成环境profile分开命名，避免Spring test profile和体验码test模式混淆。开发代理将/api转发Java，保留同源Cookie和CSRF语义；不能为省事全局关闭安全或允许任意Origin。

local与test默认使用替身；PNVS实现可以离线测试签名、请求和结果，不联网。真实sms-trial配置缺供应商、独立持久化、HTTPS origin或全站额度时拒绝启动；production拒绝。开发完成不代表允许正式健康数据或真实付费调用。

## 4. 构建、自动检查与接口文档

- 后端：编译、领域单测、真实MySQL／Redis的关键集成测试；M2再加真实RabbitMQ隔离测试。可使用Testcontainers或Compose，环境不可用时明确跳过／阻塞，不伪装通过。
- 前端：TypeScript类型检查、生产构建、请求与状态恢复检查；浏览器端到端使用两个独立会话和合成账号。
- CI：锁定版本、构建、必要集成服务、执行测试、保存结果；依赖缓存不包含私有数据。未运行的远端CI不得写成已通过。
- 输出OpenAPI含E01–E27全部端点、错误、约束和安全；健康检查之外不公开敏感配置。必要的受控运维端点与用户API分开。

## 5. 双实例与依赖故障

Nginx代理同一组Java实例，使用共享MySQL和Redis；不要依赖粘性会话掩盖共享失败。证据要能指出请求实际到达不同实例，但内部实例ID放测试日志／仅测试响应头，不在产品页面显示技术信息。

验证实例退出后另一个仍可读取已提交业务；这只证明应用实例容错，不等于MySQL／Redis／MQ高可用。Redis会话故障明确拒绝身份相关操作；统计缓存故障回源并短时熔断；MQ故障不阻止M1记录保存和原有提示。

就绪检查区分进程存活与核心依赖可用；日志记录时间、requestId、操作与错误码，M2另有eventId／taskId及重试次数。监测响应错误、磁盘、备份新鲜度、独立清单状态；M2增加积压与失败任务，不宣称已有外部告警渠道。

## 6. 运维能力迁移

- 旧每小时备份／5分钟运行检查作为能力参照，Java提供等价脚本及调度配置，不直接运行旧SQLite脚本处理MySQL。
- MySQL一致性备份含结构、算法版本、发布版本和校验摘要；独立删除清单另行保管且不可随旧快照回退。备份不打包实际env、短信凭据、体验码配置；合成环境若需身份配置仅按受控私有流程处理，不放公开制品。
- 恢复验证：临时库恢复→校验结构／约束→接最新清单→重放删除→重新建立测试会话→只读核对数据；不发送短信、不覆盖现有服务。
- 支持工具：列出受限工单、按真实业务ID标记RESOLVED，具备操作者与时间记录；读取前完成注销同步。不要把工具变成能随意修改他人体重的后台。
- 文档分别记录备份完成、恢复演练、本地／服务器运行、浏览器／手机实机。没有做过异地恢复、加密或外部告警时不要声称生产灾备完成。

## 11. 2026-10-29 MyBatis-Plus 落实

此前分层重构使用 JdbcTemplate，偏离了本项目约定；本次改为实际使用 MyBatis-Plus 3.5.18。用户、小组、成员、活跃成员关系和工单通过实体、BaseMapper 与 Lambda 条件构造器访问，行锁、条件写入、原子递增、upsert、联合查询和复合主键操作使用明确的 Mapper SQL。Repository 保持调用接口，Service 的业务与事务边界保持原有约定。

独立隐私删除日志使用单独的 MyBatis-Plus SqlSessionFactory 和仅在该工厂注册的 JournalMapper；命名锁始终由同一会话连接获取和释放。删除日志先自动提交到独立库，再在业务事务中执行清理与重放游标更新。业务库与日志库使用语句级本地缓存。数据库结构无需变更，原 Flyway 迁移内容未修改。

验证与构建结果见 [MyBatis-Plus 验证记录](evidence/mybatis-plus-2026-10-29.json)。本次不代表重新完成浏览器、双实例或生产部署验收。

## 12. 2026-10-29 Service／Mapper 架构整理

以当前模块化单体为基础，统一常规 Controller → Service → Mapper → MySQL 调用结构。移除 UserRepository、LoginRepository、RoomRepository、SupportRepository、ExportRepository、HealthRepository、IdempotencyRepository；迁移调用方，有效的实体组装与更新条件归入所属 Service。

小组业务拆分为生命周期、体重记录、提示、查询与写用例编排，各自承担实际职责；Mapper 按小组、成员、活跃成员关系、体重记录、开始预览、提示回执拆分。重复的成员资料查询合并。RoomApplicationService 和 Mutations 保留幂等、权限与事务边界，提示领取和体重写入要求已有事务。运维工单入口改为调用 SupportService。

独立删除日志移到 privacy/journal，保留独立会话、锁与删除重放职责。HTTP 基础设施归入 common/web，安全配置归入 common/config，小组到期 Advice 归入 room/web。验证码、限流、幂等查询模型从原 Repository 内部类型移出，系统响应归入 DTO。详细目录、各层职责和阅读路径见 [后端架构](../apps/java-api/README.md)，实际验证见 [架构整理验证记录](evidence/service-mapper-architecture-2026-10-29.json)。

## 13. 2026-10-30 Redis 用途与配置口径（仅文档）

- 用途分工：Session（已实现）、实时事件广播（B10，见 [12](12-实时动态与事件推送.md)）、统计缓存（B9 可选）、限流（B9 可裁剪）。其余不引入，理由见 [11 Redis 使用方案](11-Redis使用方案.md) 第 8 节。
- 配置约定：连接沿用 `spring.data.redis`，超时 2 秒；四类用途共用一个实例、不同命名空间：`shangcheng:java:{mode}:session`、`...:room:snapshot:*`、`...:room:events:*`、`...:rate:*`。不新增 Redis 依赖或独立连接池。
- 容量与淘汰：会话、缓存、事件通道共用实例，因此不配置 `allkeys-lru`；按房间数估算容量（8 人 × 90 天 ≈ 20 KB／键），不设淘汰策略。事件本身不占存储（Pub/Sub 无持久化）。
- 实时通道的工程要求：SSE 连接走异步请求，不占用请求线程；Nginx 需对该路由关闭 `proxy_buffering` 并把读超时放大（如 3600 秒），同时保留全局 `Cache-Control: no-store`；实例侧对连接总数设上限，防止连接耗尽。
- 新增 `rooms.stats_version`（Flyway V2）而不是复用 `rooms.version`；迁移脚本一经执行不得改原文。
- 本次未改 `application.yml`、未新增迁移、未写代码；B9／B10 实施时在此补充实际配置、Nginx 片段与联调环境版本。
