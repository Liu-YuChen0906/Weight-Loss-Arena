## 3. 性能、缓存与实时（B9／B10，M1 之后、M2 之前）

B9 的实现口径见 [11 Redis 使用方案](11-Redis使用方案.md)，B10 见 [12 实时动态与事件推送](12-实时动态与事件推送.md)。以下条目全部属于"未实施"，不得在压测或联调前声称通过。

### 3.1 快照与缓存（B9）

| ID | 通过标准 |
| --- | --- |
| P01 | 快照响应与无缓存实现逐字段一致（去掉 requestId）：三个 range、含准备起点成员、当日已有记录，均覆盖 |
| P02 | 写后可见，无需等 TTL：新增／覆盖记录、加入、退出、准备、改名、开始、到期，下一次请求都返回新内容 |
| P03 | 旧版本不覆盖：读旧版本与写入＋bump 交错 100 次，最终读取等于数据库最新值，Redis 中不存在被读取的旧版本键 |
| P04 | 单飞有效：同一键 20 并发冷启动，重建次数为 1，重复回源被锁挡住；锁失效时只多算一次，不写坏数据 |
| P05 | 降级正确：注入缓存异常后请求仍返回正确结果、错误率不升高、熔断后不再阻塞；Redis 整体不可用时认证明确 503，不匿名放行 |
| P06 | 跨日与跨实例：业务日期变化后键随之变化；java-1 写入、java-2 立即读到新版本 |
| P07 | 注销清理：注销后旧缓存不可读、迟到重建不写回、键索引被清空；不使用 SCAN／FLUSHALL |
| P08 | 限流（若实施）：同键 100 并发计数精确、窗口过期重置、Redis 不可用时拒绝而非放行；付费额度仍以 MySQL 为准 |

### 3.2 实时动态（B10）

| ID | 通过标准 |
| --- | --- |
| R01 | 连接鉴权：非成员、已退出、已注销用户请求事件流一律 401／403，不建立连接 |
| R02 | 无幽灵事件：事务回滚、校验失败、幂等重放不产生事件；成功提交后 1 秒内到达 |
| R03 | 双实例投递：客户端分别连 java-1 与 java-2，经由任一实例写入，两端都在 1 秒内收到 |
| R04 | 降级：断开 SSE 或停止 Redis 后，前端在 60 秒内靠版本轮询继续更新并提示"实时更新已暂停"，不报错不卡死；恢复后自动回到推送 |
| R05 | 连接管理：每用户每房间仅 1 条（新顶旧）；断开、超时、注销后注册表与订阅被清理；空闲 30 分钟除心跳外零请求 |
| R06 | 注销与登出：跨实例关闭该用户全部连接，之后不再收到事件，重连被拒绝 |
| R07 | 事件内容：只有 kind、actorId、actorNickname、at，无体重、身高、手机号；Redis 中不出现身体数据 |
| R08 | 发布隔离：Redis 发布失败时业务提交仍成功，仅记录告警与计数，不出现 5xx |

## 4. 固定样本

fixtures/domain-cases.json 包含直接从当前纯领域实现生成的合成预期值（标明来源）。用Java独立实现跑对照，不能把这些输出当线上真实用户结果。

- 北京时间：2026-10-13T15:59:59Z为10-13，16:00:00Z为10-14。
- 2026-10-01开始28天，10-03锚点，10-01=70、10-03=69.5：2/3、66.67%、变化-0.50、-0.71%，10-02无点。
- 本期首条70，近7天内69及68.5：末值变化-1.50、-2.14%，不改成-0.50。
- 10-03加入且当天一条：分母1，概况change=null。准备值不影响这组计算。
- 把测试Clock推进到结束后，不能在开发服务器真的修改系统时间。

## 6. 证据格式与完成条件

每条记录：ID、代码版本或源码摘要、命令／步骤、隔离环境与依赖版本、输入、预期、实际、通过／失败／阻塞、日志／截图路径、日期。对每阶段至少包含正常与关键失败路径，不写只镜像实现的无效测试。

性能数据单独记录固定数据规模、资源、并发、响应p50/p95、吞吐、错误率、SQL次数和缓存命中率；同条件对照，不预设提升百分比。单节点演示不称高可用，合成压测不称真实用户量。手机键盘／安全区未实机就记待验，不拿桌面截图替代。
