# 秤群结队 · 联机测试

更新：2026-10-14（北京时间）。[在线测试版](https://101.132.150.197)已部署到用户指定的 Ubuntu 云服务器，不依赖个人电脑保持开机。仅用于合成数据体验，未开放真实健康数据或收费。

## 怎么体验

两人各使用一个体验码登录 → 一人创建小组并分享邀请链接 → 另一人加入 → 双方准备 → 创建者确认开始 → 各自记录并查看共享数据。同一码重新登录恢复同一身份。

体验码保存在本机私有[体验账号](../var/test/体验账号.md)，不提交 Git 或公开网页。账号 1–4 供人工体验，5–8 预留验收。体验码是登录凭据，小组邀请码只用于加入；请勿共用账号或公开体验码。此环境不收集手机号，短信接口关闭；正式产品仍按手机号优先方向推进。

## 部署位置

| 项目 | 当前配置 |
| --- | --- |
| 公网入口 | `https://101.132.150.197`；Nginx 反向代理，HTTP 转 HTTPS |
| 代码 | `/opt/payathon-test/current` 指向带时间戳的发布目录 |
| 应用进程 | `payathon-test.service`，独立非登录用户，开机自启及失败重启 |
| 后端端口 | 仅 `127.0.0.1:4181` |
| 测试数据库 | `/var/lib/payathon-test/test.sqlite`；未复制本机开发数据库 |
| 配置 | `/etc/payathon-test/app.env`；体验码摘要在同目录 `accounts.json` |
| 运行时 | 隔离 Node 24.19.0、Certbot 5.8.0；不设置系统全局 Node |
| HTTPS | Let's Encrypt IP 证书，私钥仅存服务器 |
| 续期 | `payathon-cert-renew.timer`，每 6 小时检查并在成功后重载 Nginx |

证书方案依据 [Let's Encrypt 官方 Certbot 说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)，使用 `shortlived` profile 与 webroot。当前证书有效至北京时间 **2026-10-21 05:08:14**。定时器已启用；首次测试 CA 演练遇到临时限流，超过要求等待时间后复验通过，包含证书挑战和 Nginx 重载 hook。现有可信证书保持有效；后续实际续期仍由定时任务执行。

## 维护入口

SSH 主机指纹保存在本机私有 `var/test/known_hosts`。项目根目录连接：

```sh
ssh -o UserKnownHostsFile=var/test/known_hosts root@101.132.150.197
```

服务器上查看运行状态：

```sh
systemctl status payathon-test.service
journalctl -u payathon-test.service -n 50 --no-pager
systemctl list-timers payathon-cert-renew.timer
curl -fsS https://101.132.150.197/api/v1/health
```

`deploy/` 保存首次环境准备、先检查后激活的发布脚本、Nginx／systemd 配置和只读持久化核对脚本。后续发布保留已有 HTTPS、账号配置与数据库；首次准备脚本不用重复运行。打包要排除 macOS 元数据，且不能包含 `var/`、`.env`、体验码明文或 `.git/`：

```sh
COPYFILE_DISABLE=1 tar --no-xattrs -czf /tmp/payathon-test-release.tgz apps packages db scripts tests deploy package.json package-lock.json .node-version
```

公网验收脚本为 `scripts/online-check.mjs`，默认使用账号 7／8，`QA_ACCOUNT_START=5` 使用 5／6。脚本会写入合成数据，不能指向真实数据环境。Playwright 路径沿用 README 的可选浏览器检查配置。
