私有配置位于 Git 忽略的 `var/private/sms-auth.env`，创建时文件权限 0600；用户已报告保存，本轮通过离线缺项／格式检查并核对权限 0600 与 Git 忽略；未输出配置值。控制台登录密码不用于程序配置。无凭据示例是 `deploy/sms-auth.env.example`，与普通短信示例分开；当前 `sms-check` 已支持 PNVS 数字模板，仅检查缺项／格式，不代表云端凭据或权限有效。不要在聊天、文档、日志或提交中保留真实凭据，也不将配置齐全视为送达验证。

官方[个人开发者指南](https://help.aliyun.com/zh/pnvs/use-cases/sms-verify-for-individual-developers)明确支持个人实名认证、Web／H5、系统预置签名与模板，无需企业营业执照或自行申请签名模板。上述开通和资源准备已完成，不再要求用户重复办理。[新手指引](https://help.aliyun.com/zh/pnvs/getting-started/sms-authentication-service-novice-guide)说明快速测试需绑定测试手机号且测试会计费；此前查阅的[计费说明](https://help.aliyun.com/zh/pnvs/product-overview/product-pricing/)为月使用量不超过 1000 次时 0.06 元／次，核验免费，按运营商送达回执计费，套餐优先抵扣；实际联调前核对最新控制台价格及余额。费用计入开通服务的主账号，`shangcheng-sms` 只是调用身份，[RAM 用户不独立计费](https://help.aliyun.com/zh/ram/support/)。产品用户通常不因接收验证码承担短信接收费用。

注意产品边界：普通短信使用 `Dysmsapi/SendSms`，短信认证使用独立 `Dypnsapi/SendSmsVerifyCode`／`CheckSmsVerifyCode` 接口与资源。已提供独立 PNVS 适配及离线预检，数字模板不能交给普通短信适配器。下一步在指定手机号及发送条数后独立联调。助手尚未替用户创建云资源、充值或发短信。

已有普通短信适配依据：[SendSms](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)、[V3 签名](https://help.aliyun.com/zh/sdk/product-overview/v3-request-structure-and-signature)。其[使用须知](https://help.aliyun.com/zh/sms/user-guide/usage-notes)要求企业资质；与上方个人可用的短信认证属于不同产品，已有代码不要求用户取得企业主体。

## 第一批：手机号登录的工程准备

关联任务：BASE-02、PRE-02、PRE-06、D02。

### 可以直接推进

- 沿用 `/auth/code`、`/auth/login` 与当前会话接口，确定投递适配器的输入、超时、明确失败及未知结果处理；不向浏览器或日志返回真实验证码、完整手机号或供应商原始报文。
- 本批已补齐验证码从待发送到可验证的状态管理、过期／失败处理和并发协调，修复先写 OTP 即可验证及缺少适配器仍留下 OTP 的初始问题；超时／失败不能验证，受理不表示已送达。
- 先用可控替身验证投递成功、拒绝、超时、重复请求及同手机号重新登录；通过适配器契约测试不等于真实短信送达。
- 设计独立正式运行配置及缺项时拒绝启动的规则。当前新增独立 sms-trial，要求精确 HTTPS、回环代理、独立持久库、PNVS 配置及 1–20 的明确全站日上限；已部署值为 10。local 仍拒绝非开发短信，test 仍禁止手机号登录；正式 production 仍未开放。
- 保留测试站、原有体验码和库。新增配置示例不含凭据；供应商密钥只配置在服务器私有配置中。

### 外部联调前需落实

账户、个人主体、赠送签名／模板及私有配置准备见上方最新状态。后续验证凭据有效性、权限、余额与费用预算；不重复要求用户申请企业资质、创建 RAM 用户或重新发送密钥。凭据不写入聊天、仓库或备份明文的通用配置示例。

完成真实短信到手机、正确／错误／过期验证、退出重登恢复同一身份、重发限流及配置失效检查后，才记录“真实短信联调通过”。正式运行还需数据控制和部署准入验收，不因登录可用便开放健康数据。

### 离线接入预检

检查器已支持 `aliyun-pnvs`（数字模板）及 `aliyun`（`SMS_...` 模板）。PNVS 示例在 `deploy/sms-auth.env.example`，真实值只放 Git 忽略的 `var/private/sms-auth.env`，不填写仓库示例。默认检查：`node scripts/sms-check.mjs`；载入当前配置：`node --env-file=var/private/sms-auth.env scripts/sms-check.mjs`，本机 Node 完整路径见 README。本轮当前私有配置离线检查通过。

工具报告缺项／格式问题，退出码 0 表示格式齐全、1 表示需补充；不打开数据库、不启动服务、不联网、不发送短信，不输出配置值。`ok:true` 也固定标注 `scope:CONFIGURATION_ONLY`、`deliveryVerified:false`；不能证明凭据有效、签名／模板已审核、余额充足或手机可接收。已使用官方固定向量验证 ACS3 签名，但真实供应商验签仍待联调。

### 短信接入接续步骤

1. **已完成**：核对官方 [SendSmsVerifyCode](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)／[CheckSmsVerifyCode](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)，使用固定 `dypnsapi.aliyuncs.com` endpoint。发送占位符由平台生成六位数字码，五分钟有效，不取回真实验证码；显式覆盖旧码、60 秒间隔、关闭自动替换签名重试。远程核验仅匹配流水号且返回 PASS 时成功，UNKNOWN 表示验证码未通过；原始报文不透出。
2. **已完成**：`sms.mjs` 提供带 `verifyCode` 的 PNVS 投递函数；`service.mjs` 保存核验方式标记，核验成功前不创建账号或会话，HTTP 等待异步结果。同手机号核验时拒绝并发核验／重发，最多五次；超时／异常作废本次码，8 秒边界内取消，不自动重试。过期、已删除、流水号变化及迟到 PASS 都不能签发会话。开发码、体验码及现有运行准入保持。
3. **已完成**：内存库／替身网络与临时 HTTP 端口验证上述路径，72 项自动化测试通过。真实私有配置仅离线检查，缺项／格式通过、权限 0600、Git 忽略，不输出值、不联网、不改现有库。保存配置不等于供应商验签或送达通过。
4. **已部署、待用户手机验收**：用户决定自行输入手机号测试，并明确授权部署／清空旧账号。已补独立 sms-trial 入口，只有用户点击获取才调用付费发送接口；全站每天最多 10 次请求，失败／未知也计入，重启不重置。手机页面、HTTPS／Secure Cookie、隔离替身流程、空库及备份监控已验证；真实收码、正确／错误／过期／重登／限流及配置失效仍待实测。助手未代发，不放宽 local／test 或 production，不开放真实健康数据。

## 第二批：数据控制的规格与实现

关联任务：PRE-03、PRE-06、SUP-01、SUP-02、OPS-01、D09。以下候选处理方式仍需用户确认，不因写入本文件成为已批准要求。

### 已确认的基础方向

- 本人取回数据和隐私处理属于基础能力；开营后无普通退出，不妨碍隐私请求。
- 不设计独立撤回共享功能；导出、注销删除和支持请求保留。
- 删除与账号注销要覆盖在线身体数据、关联缓存及可还原这些数值的结果；恢复旧备份时必须先重放删除清单，再允许业务访问。
- 身高不在组内展示；是否以及多久持久保存仍须明确。目标算法与数据保留政策分别处理，低 BMI 不再讨论为待定条件。

### 需要一次明确的产品决定

| 事项 | 建议供下一轮确认 | 决定后影响 |
| --- | --- | --- |
| 正常保存 | 先明确历史复盘需要保留到何时，以及长期不活跃账号是否清理，再给账号／每期／身高分别定期限；暂不自行填入无限期或任意天数 | 到期清理、历史页面和隐私文本 |
| 删除范围 | 建议区分“保留账号、删除本人某期数据”和“注销账号、删除全部本人数据”；按天删除、补录等不随本轮默认增加 | 确认界面、导出、幂等记录清理和历史复盘 |
| 在线及备份时限 | 在线立即停止相关访问，实际清除时限、备份滚动保留天数、删除清单保留时长及处理完成判定一起确认 | 清理任务、备份淘汰、删除重放和状态展示 |
| 小组特殊状态 | 删除／注销后不足 2 人、开始权限持有人注销、空组及已结束期如何处理，需要写明；建议让其余成员既有记录保持可用，不代他们提前结束本期 | 状态迁移、权限交接、邀请及复盘 |

### 可以先推进的技术工作

继续完善注销的恢复保护、支持工具与删除清单；按范围删除只在确认范围后实现。保留策略未确认前不启用清理任务，不把待定天数埋进默认值，不增加独立撤回路由或成员状态。

注销沿用 `DELETE users` 级联清理，并已新增独立删除清单与恢复重放；权限交接仍沿用已有的待开始且本人持有权限场景。支持工具也使用指定独立清单，读取工单前先补处理未完成的注销。新增按范围删除仍需检查幂等响应、准备字段、提醒及历史数据，不能只删 `records` 一张表。

正式数据备份还需加密与密钥管理、独立清单的异地持久化及可验证的淘汰。新版工具已兼容结构 1／2 并在业务读取前重放注销，当前服务器已同步新版，旧在线数据按用户最新要求清空；现有历史合成备份及私有副本保留，不自动恢复或拿来演练真实健康数据迁移。

## 实施顺序与验收

1. 先做手机号投递适配与发送状态的工程准备，并梳理数据控制动作和表结构变更；使用隔离合成数据验证。
2. 核验并确定短信服务商接入条件，同时集中确认上表的数据规则。目标边界沿用已确认决定，不重复确认。
3. 按确认范围完善删除、注销后的成员生命周期、保存策略及备份淘汰，更新 API 和对应文案；独立撤回共享不列入验收。
4. 在独立环境完成真实短信联调、双账号权限与删除、重试／并发、旧快照重放后不可读、手机键盘／安全区和真实网络验收。部署与真实数据开放作为独立操作记录。

当前批次已按本节开头记录完成部分工程准备与隔离验证；真实短信、具体数据规则及正式准入尚未完成。最新部署已按用户要求清空旧在线账号记录、撤销旧体验码并切换独立手机试用库；历史私有备份保留，不自动恢复。真实健康数据正式准入仍未开放。
