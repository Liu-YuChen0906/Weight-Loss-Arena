# 上秤 · 开发流程与经验

整理：2026-10-14。用于后续开发复用；当前进度只维护在[交接入口](开发交接.md)，逐批事实与截图放[开发记录](本地基础版开发记录.md)，不在这里复制流水账。

## 一批修改如何闭环

1. 从用户批注、当前页面和对应规范确定问题；区分正式应用与静态原型，核对最新用户决定。只加载当前任务相关文档与代码。
2. 将本批需求写入对应规范，再落到正式代码。局部改动保持其他流程和文案；需要补充业务决定时，继续推进不依赖答案的工作。
3. 按变更选择检查：纯外观／动效以语法与浏览器验收为主；权限、记录、目标、日期、并发等业务修改必须补充或运行有意义的相关测试，不用重复实现细节的测试凑数。
4. 在实际服务页面刷新后验证：触发动作 → 结果／错误 → 切换或取消 → 刷新恢复。数据修改还要核对 API 和持久化；单凭界面或 WebSocket／HTTP 连通不算完整成功。
5. 保存必要证据并更新任务状态、交接和开发记录。向用户简短说明现在能体验什么、怎么验收、已通过检查和仍未验证的边界。

当前协作以用户体验和产品决定为核心，不要求用户阅读代码，也不为每次小改动另写长计划、架构稿或重复总结。

## 先确认自己改的是哪一份

本地正式预览是 `http://127.0.0.1:4180`，由 `apps/api/server.mjs` 直接读取 `apps/web/` 资源；没有构建步骤和自动热更新。云端另有独立合成数据测试环境，入口与部署流程见[联机测试部署](联机测试部署.md)。本地修改不会自动发布到服务器；前端刷新才读新资源，后端模块修改需要重启对应服务。不能把本地截图当成云端版本验收。

`prototype/index.html` 与 `prototype/mobile.html` 是保留的设计工具；不要在其中修正式应用问题。过去移动原型的 iframe 缓存曾造成旧样式误判，核对原型时直接看实际页面入口。用户把静态页面作为参考时，先比对参考，不擅自修改它来消除差异。

旧总控中的固定邀请码、localStorage、默认 21 天等描述属于原型历史，不代表正式应用当前能力；反过来也不能将正式本地服务写成已经上线。

## 动效的关键不是只加 transition

- 单位切换保留表单与滑块节点，只更新选中态、数值、单位和目标；整页 `innerHTML` 重建会中断位移、焦点与输入。
- 范围和维度使用共享 `pillControl`／`selectPill`；`mountShell` 保留同一用户、同一房间内的导航，图表只更新数据区域。跨用户／跨房间不能为了动画保留旧私有内容。
- 外层滑块用 transform 负责连续位移，内层负责轻微拉伸回弹，文字短暂过渡。反向切换从当前位置衔接，不排队播放。
- 范围读请求不锁死筛选；`viewRequest` 排除过期响应，`dataRange` 用于失败回退。只读筛选的响应策略不能照搬到开营／保存等写操作；后者仍需权限、版本、幂等与未知结果核对。
- 尊重 `prefers-reduced-motion`，关闭位移与拉伸。样式存在降级规则不等于已经在真实系统设置下实测。
- 桌面纵向、手机横向的布局切换也会触发 transform 过渡；若截图刚好停在中间帧，先核对最终落点再判断布局错误，不要据此随意加偏移补丁。

代码位置见 `apps/web/app.js` 的 `switchRecordUnit`、`pillControl`、`selectPill`、`mountShell`、`refresh`，以及 `apps/web/styles.css` 末尾对应规则。

## 输入和数值不要被展示反向污染

记录内部以公斤 `recordKg` 保存原始输入值，斤只做 ×2／÷2 的展示换算；不要从已经四舍五入的显示字符串反复换算。实际验证曾用 60.125 kg 往返切换，展示 60.13 kg 后再切斤仍应为 120.25，不能累积舍入误差。

单位切换不保存；查看修改确认不保存；取消保留输入，刷新以数据库为准。界面 QA 优先只读交互，不为了截图覆盖用户已有记录。确需写入时使用隔离测试数据，明确提交前后与清理策略。

## 浏览器验收怎么做

- 先看真实页面、账号和当前路由；批注里的 URL 可能比当前状态旧。已有浏览器标签应按实际标签继续操作，不能只凭旧 URL 断言页面。
- 使用本轮可用的浏览器工具检查页面；重新绑定当前浏览器／标签，不把旧聊天的工具变量、标签 ID 或 PID 当成永久标识。
- 检查按钮选中态、焦点、快速往返、图表单位和数值、返回路径，以及固定操作区与导航的间距；不要只看一张静态截图。
- 响应式验证报告 DOM 测得的 CSS 宽度。本轮浏览器缩放使请求 330 宽实际为 375；不能把请求尺寸当作实测尺寸，也不能将 429 写成精确 430。
- 移动端关注横向溢出、三项是否同排、数值截断和底部按钮遮挡；桌面关注侧栏布局与纵向落点。临时视口验收后恢复用户尺寸。
- JavaScript 动画 API 在当前浏览器的只读 DOM 代理中可能不可用；不要反复调用不支持的 `getAnimations()`。用已支持的 DOM、截图与实际交互作证，明确未测部分。
- 连续动效在预览中体验，截图记录最终外观；实机键盘、安全区和系统偏好必须单独取得证据。

## 文档维护与交接

每类内容按总控 2.1 的分工详写一次：业务定义在 PRD、目标公式在总控 4.4、当前接口在 API 契约、验收在总控 13.1、当前任务在清单第 11 节、逐批证据在开发记录。交接只留当前状态、下一步和易误改的边界；其他文件用链接引用，不重复附流水账。精简时核对任务／验收编号、关键规则与链接，保留历史证据，区分静态原型与正式应用。

用户要求「先迈出一大步」时，以可体验的阶段成果推进，优先处理阻塞主流程的问题；不要因为清单还有未测边界，就默认继续铺开细微异常。收到笼统的积极反馈可记录为用户认可，但手机全流程、真实设备与持续使用必须另有具体证据。

业务规则在总控／PRD，视觉规则在视觉需求／个人偏好，执行状态在任务清单，证据在开发记录。交接只保留当前状态与下一步入口；经验只收录可复用结论。最新用户决定与旧文档冲突时同步相关权威文件，不让各处保留不同现行规则。

结束一批时核对新增文档链接、检查 Git 状态，保留工作区和数据库；是否已跟踪以当次状态为准，未跟踪成果不等于可删除的临时文件。未经要求不提交、推送、发布，也不将“文档已整理”称为代码已归档。

## 联机发布与验收的可复用经验

- 测试身份、数据库与正式数据环境分开；体验码明文及 SSH 指纹只保留在私有忽略目录。小组邀请链接和登录凭据用途不同，账号 1–4 留给用户，脚本只用预留 QA 身份；不得假定用户体验后这些账号仍为空。
- macOS 打包使用 `COPYFILE_DISABLE=1` 和 `tar --no-xattrs`，服务器解包排除 `*/._*`，防止 AppleDouble 文件被当成 JavaScript。先在候选发布目录执行语法与业务检查，通过后再激活，后续保留数据库、账号和 HTTPS。
- 检查脚本依赖项目工作目录；远端先 `cd /opt/payathon-test/current` 再调用 Node，不能仅使用脚本绝对路径就假定其相对文件扫描正确。
- 异步动作中的整页／弹窗重绘必须让新 DOM 按钮继承 busy 状态，最终恢复当前 DOM 中带忙碌标记的按钮；保留原本因业务条件或短信冷却而禁用的按钮。否则会出现新按钮看似可点、点击却被忙碌锁忽略的情况。
- 公网浏览器脚本按实际手机可见入口返回，操作完成后再跳转或重登；不要在退出请求未完成时强制刷新。脚本复跑还须兼容已有活动小组，不能用缺少必填准备字段造成的原生表单拦截误判登录故障。
- HTTPS 续期演练遇到 CA 临时限流时按 Retry-After 等待后有限重试，保持现有有效证书。区分「定时器已配置」「模拟续期通过」与「未来实际续期已执行」；部署细节与证据只维护在对应部署说明和开发记录。

## 在线备份与恢复的可复用经验

- SQLite WAL 在线库使用 backup API 做一致性快照，不能只复制主文件。仅将新快照改成独立单文件，源库继续 WAL。对新快照做完整性／外键／结构／全表摘要验证，再实际恢复；不要把持续变化的在线库与已完成快照强行逐字节对比。
- 临时恢复必须在新私有目录和仅本机随机端口运行；读取包内对应源码、配置及账号映射，临时会话只写副本。恢复命令不提供在线数据库写入目标，失败时清理临时目录；上线切换与整站接管属于另外的真实操作。
- 备份完成后再原子发布目录；检查最新完成包损坏时直接报错，不回落旧包来隐藏失败。备份检查包含最近任务结果与时效，目录存在或文件可打开不够。
- 通过空的临时备份目录演练检查失败及恢复，保持实际服务、实际备份与监测状态不变。状态／日志、外部消息通知与独立外部探针是不同能力，不混称已完成。
- 复制服务器备份到本机时具体说明目的地和内容。本批自动审批要求对含账号／环境配置的传输单独明确授权；取得用户授权后再执行，不能绕过被拒绝的操作。私有副本放在 Git 忽略目录；一次下载不等于自动异地同步。当前测试备份不自动清理，正式保留／删除重放需另定规则。

## 短信异常与倒计时

- 认证接口的明确 503 也可能是已知投递失败；按路径和受控错误码保留脱敏提示，不把它换成身体记录的“保存结果未知”。业务写入的未知结果／幂等策略仍需保留。
- 冷却使用服务端实际 retryAfter，失败与 429 也要启动；前端记绝对截止时间并更新当前 DOM，不能只递减已被重绘替换的旧按钮。busy 恢复、导航、切到后台都要保留冷却禁用；刷新后由服务端实际剩余值恢复，不重置为固定 60。
- 用户提供阿里云欠费通知只能作为账户状态反馈；与供应商拒绝发送相符，不代表已查清全部欠费产品或金额。用替身验证错误和倒计时，不通过循环真实发送排查；上线后保留用户现有账号及业务数据。
