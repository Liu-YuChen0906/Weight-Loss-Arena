## 1. 当前参数与确认记录

- 28天难度基准：低2%、中3%、高4%、极高5%；默认低。
- 时间节点：14天0.6、28天1、56天1.8、90天2.6。
- 其余天数采用节点间分段线性插值，精确经过四个节点；不做会偏离节点的回归，也不向14–90天之外外推。
- BMI修正改为S=clamp(BMI/22, 0.75, 1.25)：BMI22为算法基准，BMI24相对基准偏高，增加约9.09%的任务；正常BMI也生成目标。
- 不使用原先的0.5kg/周统一上限与BMI24强制终点。
- 四档比例与时间节点为产品任务规则，不代表医学处方或已验证的难度等价。
- 本稿更新算法与样例；PRD、视觉文档及静态原型中的旧三档入口待后续同步，不能视为前端已经支持四档。

旧版 v0.1 仅用于历史对照，演变要点见第 2 节；仓库未保留独立历史稿。v0.2、v0.3和讨论中的幂函数时间方案均由本版替代。

## 2. 研究依据与设计假设

NIDDK指出，减重过程中代谢会放缓，较低体重需要的能量也更少。Hall等人的动态模型研究指出，体重变化需要考虑随过程变化的能量消耗，不能简单采用固定能量缺口线性外推。
- NIDDK：https://www.niddk.nih.gov/health-information/weight-management/adult-overweight-obesity/eating-physical-activity
- 原始研究：https://pmc.ncbi.nlm.nih.gov/articles/PMC3880593/
- NIH模型：https://www.niddk.nih.gov/bwp

这些资料支持「不能假定始终按固定速度下降」，不支持把每个人实际下降都描绘为平滑递减，也不提供本产品的四档公平公式。以下时间曲线和BMI修正均为产品假设。

v0.1虽然使用幂函数，但在14–90天内衰减很弱。例如95kg高档，28天约减1.51kg，56天约3.00kg，仍然接近翻倍，未充分体现用户期望的时间难度。

## 3. 当前计算公式

```text
H = 身高m
W = 起始体重kg
T = 本人参与天数，整数14–90
BMI = W / H²

d = {低: 0.02, 中: 0.03, 高: 0.04, 极高: 0.05}
S = clamp(BMI / 22, 0.75, 1.25)

14 ≤ T ≤ 28：F(T) = 0.6 + (T − 14) × 0.4 / 14
28 < T ≤ 56：F(T) = 1.0 + (T − 28) × 0.8 / 28
56 < T ≤ 90：F(T) = 1.8 + (T − 56) × 0.8 / 34

计划减重 L = W × d × S × F(T)
目标体重 G = W − L
```

clamp表示将数值限制在给定区间。单位转换与内部计算保持精度，目标体重最后统一舍入两位；展示减重量从起始值减最终展示目标推导。

### 3.1 四档的含义

当BMI=22且周期为28天，低／中／高／极高分别减起始体重2%／3%／4%／5%。80kg对应1.60／2.40／3.20／4.00kg。实际BMI不是22时，再乘S，不能把基准比例误读成所有人的最终比例。

四档每相邻一档增加1个百分点；相对任务增幅依次为50%、约33.3%、25%。

### 3.2 身高如何参与

同体重但身高不同，BMI会不同。现在以22作为产品算法参考值；高于22时适当增加任务，低于22时适当减少任务。22不是资格门槛或减重终点，本次调整不重新定义医学上的BMI分类。

| BMI | 体型系数S | 相对基准任务的调整 |
| --- | --- | --- |
| 18.5 | 0.8409 | 约减少15.91% |
| 20 | 0.9091 | 约减少9.09% |
| 22 | 1.0000 | 不调整 |
| 24 | 1.0909 | 约增加9.09% |
| 26 | 1.1818 | 约增加18.18% |
| 27.5及以上 | 1.2500 | 最多增加25% |

这里「增加9.09%」指原基础任务乘1.0909，不是给难度基准额外加9.09个百分点。上下25%的调整范围保持不变。

BMI修正是有限的公平假设，无法区分脂肪与肌肉，也无法识别已有减重经历。它不保证同等完成率。

| 天数 | 时间系数 | 相对28天任务 |
| --- | --- | --- |
| 14 | 0.6000 | 60.0% |
| 21 | 0.8000 | 80.0% |

| 42 | 1.4000 | 140.0% |

因此本版不是每一阶段都进一步减速：14–56天日增量相同，56天后日增量下降。各节点连续，累计任务持续增加，日增量不递增。

14天0.6是短周期任务设置，不向14天以下外推；90天以上亦不外推。节点为产品约定，未由人体实验拟合，只决定本期总任务，不作为每日掉秤要求或实际变化预测。

## 5. 公平性仍存在的限制

本稿把公平具体化为：同档采用同一规则、公斤负担随体重变化、相对负担按BMI有限调整、长周期边际任务下降。它不等于相同主观努力或相同达标概率。

必须区分「房间进行了多久」和「本人已经减重多久」。一个已连续减重半年的人与刚开始的人，即使当前身高体重一样，也可能面对不同难度。现有三个数值输入无法识别这一点。因此本稿时间衰减解决的是本期时长规则，没有解决全部个人减重历史问题。

若下一步引入连续减重历史，应考虑基于同一减重阶段的原始基准和累计时间计算剩余任务，避免换房间就重置初期预算。不能只记录最近一次房间天数便宣称知道个人代谢阶段；是否增加相关输入另行讨论。

也不自动生成「每天必须掉多少」的催促，不用单次最低体重评判完成，不按超额减重额外加分。若增加完成率，起始与结束读数应采用一致测量口径；当前准备体重只是本人输入值。

## 6. 自动建议的边界

本版取消正常BMI不生成目标及0.5kg/周的通用硬限制，允许用户查看四档并选择。成人声明继续按现有产品规则执行，不新增按65岁或高BMI一刀切的排除。

2026-10-14 用户明确决定：不增加起始BMI或目标BMI偏低时的限制，保留当前算法。通过现有输入校验的成年用户均按同一公式生成并提交目标；BMI低于18.5不额外阻止准备或参与，不截断目标、不自动改为仅记录模式。此前“不提交起始或目标BMI<18.5的自动建议目标”仅为候选建议，现已被本次决定取代，不再作为待冻结项。

疾病、孕期、哺乳期、治疗或明显高肌肉量情况下，通用BMI公式可能不适用，不宣称这种标准化结果适用于所有成年人。产品不提供热量处方、用药方案或医学结论。

## 7. 流程与实现建议

- 同一房间共享难度，成员使用各自身高体重和参与天数计算。
- 待开始阶段目标可预览；正式开始锁定算法版本、输入、参数与结果。
- 改周期或难度后重新计算、请成员确认新目标，不能静默替换已接受的任务。
- 身高继续只用于计算，不在组内展示。
- 服务端保存并计算权威目标，客户端用于预览。
- 两位小数只是展示精度，不代表算法对人体有0.01kg预测能力。
- 原型、PRD与总控暂不随研究稿自动定案。

## 8. 验证状态

本版40组表格样例由JavaScript统一生成，均经过四档顺序、目标与减重量显示一致性及目标BMI检查。

另按身高140–210cm（步长5cm）、BMI18.5–40（步长0.25）、天数14–90枚举100,485组，检查四档顺序、时间单调性、分段日增量不递增与节点连续性。该枚举仅检验上述范围的算术一致性，不证明个体效果或适用性；第6节现按用户最新决定不设低BMI限制。

这些检查只验证公式与表格一致，不验证个体达标概率或医学效果。后续需要按BMI、周期和减重经历分组观察目标理解程度与挑战感，再讨论是否调整参数。
