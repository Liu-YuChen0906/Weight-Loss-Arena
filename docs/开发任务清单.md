**ROOM-03 必须实现的算法口径：**

```text
H = 身高 cm / 100；W = 起始体重 kg；T = 本人参与天数（14–90 整数）
BMI = W / H²；S = clamp(BMI / 22, 0.75, 1.25)
d = 低 0.02 / 中 0.03 / 高 0.04 / 极高 0.05
F(T)：14→0.6、28→1.0、56→1.8、90→2.6，节点间分段线性插值
计划减重 = W × d × S × F(T)
目标体重 = W − 计划减重
```

保留中间精度，最终目标统一舍入两位，展示减重量由起始值减最终展示目标推导。算法版本与本期目标锁定，升级不静默改旧目标。正常 BMI 也生成目标，不恢复旧的 0.5 kg/周统一上限或 BMI 24 终点。低 BMI 配套行为按 PRE-03 决策实现。样例至少包含 175 cm／80 kg／中档：14 天 78.29 kg、28 天 77.15 kg、56 天 74.87 kg；另检验四档顺序、BMI 系数上下界、四个时间节点与非节点插值。算法测试通过仅证明算术一致，不证明医学效果或公平性。

### 4.3 当日记录、统计、到期与提醒

- [ ] **DATA-01｜服务端日期与生命周期模块**  
  依赖：BASE-01、PRE-05。关联：A06、A20。产物：可注入时钟、`Asia/Shanghai` 业务日期、UTC 时间戳、有效期判断。验收：周期为 `[开始日 00:00+08:00, 开始日+N天 00:00+08:00)`，显示最后一天 23:59；实际开始成功前不可记录、结束瞬间及以后不可写；设备时区变化不改业务日，后台停机也不能延长权限。
- [ ] **DATA-02｜本人当天体重创建与覆盖**  
  依赖：ROOM-05、DATA-01、BASE-04。关联：A05、A06。产物：当天记录 API、公斤／斤输入、覆盖前后值确认、唯一键与版本控制。验收：70 kg＝140 斤；先转 kg 再校验、一次舍入保存，切换单位不累计误差；每人每日一条，待开始／结束不可写；他人不能代写。跨日返回 `BUSINESS_DATE_CHANGED` 并保留输入重新确认；多设备冲突展示最新值，保存结果未知先核实，不假报成功；首版无历史补录、离线自动提交。
- [ ] **DATA-03｜统一统计与分析接口**  
  依赖：DATA-02、ROOM-06。关联：A07、A22。产物：成员概况、个人 7／28 天、全组体重／变化／比例、复盘统计。验收：变化基准始终是本期首条有效记录，不是准备体重或区间首条；覆盖率起点取区间起点、本期开始日、本人加入日最晚者，锚点不晚于截止日；无／单／缺失记录正确处理。数据修改／删除重算缓存，负零显示统一，成员目标有可达查看位置且不增加额外图表维度。
- [ ] **DATA-04｜自动到期、只读复盘与历史列表**

  依赖：BASE-02–BASE-04、PRE-06。关联：D09、A12。产物：可达支持入口、受理记录与状态、本人数据取回、撤回共享、删除及注销流程。验收：不是 toast 或孤立函数；验证本人、请求可追踪，按冻结时限处理；数据取回不收费。开营后不能普通退出，不影响隐私申请受理。
- [ ] **SUP-02｜落实撤权、删除与成员生命周期**

## 7. P2 / M2：基础完成后评估收费，再做支付交付

本节为条件任务；列入清单不代表批准收费功能、价格、AI、商户开通或生产发布。PRE-07 调查不阻塞无关基础模块。仅当基础完成并确认 D01 后，才进入商品与付费界面实现。

- [ ] **PAY-01｜评估并确认一个收费场景**  
  依赖：基础功能完成，QA-02 具备试用条件。关联：D01、D06。产物：比较部分现有功能收费与新功能收费的价值、真实反馈、成本、复用频率、隐私及交付风险，形成用户确认的单一方案。验收：明确是否收费、收费对象与权益边界；不默认采用 AI 报告，不新增多档会员、自动续费或付费墙。
- [ ] **PAY-02｜冻结商品及售后契约**  
  依赖：PAY-01、PRE-07、PRE-06。关联：D01、D05、D09。产物：商品／价格版本、购买资格、服务对象／次数或期限、交付格式与时限、查阅期限、重复购买、退款与支持政策。验收：价格、收款主体与承诺可公开核对。若为报告，先定义最低数据条件与数据版本，购买前检查可生成性；首版建议只用本人数据，涉及组员数据须另有授权；具体退款模式经确认，不能直接把「建议全额退款」当作已批准。
- [ ] **PAY-03｜冻结接入方式与支付数据契约**  
  依赖：PAY-02、PRE-07 资格结论。关联：D05、总控 7／9。产物：基础网页收款或即刻收选定路径、官方 SDK／接口版本、订单／事件／权益／交付／退款／任务模型及 API。验收：按官方当前材料确认签名、查询、通知、退款及参赛统计路径；即刻收若用官方托管权益，以官方查询授权，不能套用自造通知。业务用户与扫码付款者分离，订单服务归属固定。
- [ ] **PAY-04｜订单创建、收银与结果恢复**  
  依赖：PAY-03、BASE-04。关联：A09。产物：商品页、服务端下单、整数分金额快照、幂等订单、收银打开、本人订单与状态查询入口。验收：客户端不能改价／收款方／归属；连点与重试不重复建单；取消／超时／关闭／未跳回保留可查询状态；浏览器回跳不能授予权益。结果有限轮询后提供刷新与后台核实，内置浏览器不支持时有明确兜底。
- [ ] **PAY-05｜可信支付确认、权益与幂等交付**  
  依赖：PAY-04、OPS-01。关联：A09、A10、A16。产物：选定路径的可信支付确认、校验与事件去重、权益事务、持久交付任务、本人查阅／恢复入口。验收：基础支付通知验签并校验应用／商户、订单、金额及最终状态，丢通知可主动查单；支付、交付、退款分开记录。交付失败可追踪及有限重试，支付成功不伪称已交付；退款／撤权后旧任务不得重新开放结果。
- [ ] **PAY-06｜退款、对账与暂停新售**  
  依赖：PAY-05、SUP-01、SUP-02。关联：A09、A10、A16、A17。产物：本人退款申请、最小管理权限与审计、唯一退款号、查询补偿／对账任务、异常清单和停售开关。验收：退款超时沿原退款号核实，不重复退款；退款成功撤权／取消任务；关单与付款竞态补交付或退款。注销立即受理，未决交易隔离售后；停售仍可查单和支持；备份恢复先重放隐私删除、重对账再恢复交付。
- [ ] **PAY-07｜收费功能界面与条件性 AI 实现**  
  依赖：PAY-02、PAY-05；AI 另需 D06 确认。关联：A10、A11、A16。产物：仅选定商品所需购买、处理中、交付、失败、订单及售后界面。验收：用户看清购买对象、价格与承诺，未知结果不引导重复付款；若选报告／AI，数据版本、模型预算、第三方数据流与删除联动明确；未选择 AI 不安装或调用模型服务。
- [ ] **PAY-08｜沙箱异常及生产小额全链路验证**  
  依赖：PAY-04–PAY-07；生产部分需已开通资格与生产发布条件。关联：A09、A10、A16、A17。产物：通知重复／乱序／伪造／丢失、数据库失败、关单竞态、重复付款、交付失败、退款未知及注销并发的验证记录；真实付款→正确账号权益→真实交付→退款撤权证据。验收：沙箱与生产分别标注，支付截图或成功页不能代替生产闭环；测试交易不混入真实用户价值指标。
