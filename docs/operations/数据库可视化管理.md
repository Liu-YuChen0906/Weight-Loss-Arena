# 上秤 · 数据库可视化管理

采用 sqlite-web，直接连接服务器当前手机试用库，通过 SSH 在本机浏览器操作。管理工具是独立服务，不依赖个人电脑保持开机，也不改变上秤应用的发布目录。

## 打开和关闭

1. 在项目文件夹双击 [打开数据库管理.command](../../打开数据库管理.command)。
2. 浏览器访问 `http://127.0.0.1:18888/`，登录密码见本机私有 [数据库管理入口](../../var/private/数据库管理入口.md)。
3. 管理结束后可双击 [关闭数据库管理连接.command](../../关闭数据库管理连接.command)，仅关闭本机 SSH 连接。

第一次建立新连接前，打开脚本会触发一次服务器内备份。电脑重启或网络断开后重新打开脚本即可；如果本机 18888 端口被其他程序占用，脚本报错，不会打开错误服务。

密码只保存在 Git 忽略的本机私有文件及服务器 root 0600 的 `/etc/payathon-database-admin.env`，不在公开文档、源码包或聊天中输出。

## 主要表和操作

| 表 | 内容 |
| --- | --- |
| users | 账号、昵称、手机号、同意状态及当前小组 |
| rooms | 小组名称、周期、状态和邀请码 |
| members | 小组成员、准备状态、目标及起始输入 |
| records | 每日体重记录和修改版本 |
| support_requests | 支持工单 |

点击表名后，Content 查看／筛选数据，Edit 修改，Insert 新增，Query 执行 SQL，Export 导出。这里直接操作在线数据库，修改后应用会读取新值。sqlite-web 已开启外键检查。

账号注销仍通过上秤的账号入口完成，才能同步处理关联数据、权限交接和独立删除清单；直接删除 users 行不等于完整隐私注销。修改身体记录时注意 version 及成员／小组关系。sessions、otp、rate_limits、privacy_meta 为系统表，日常查看账号和记录无需修改它们或表结构。

## 服务位置与维护

- 工具：独立 Python 虚拟环境 `/opt/payathon-tools/sqlite-web-venv`，sqlite-web 0.8.2。
- 入口封装：`/opt/payathon-tools/database-admin/server.py`，源码在 `deploy/database-admin.py`。
- 服务：`payathon-database-admin.service`，非 root 的 payathon-test 用户，开机启动。
- 目标库：`/var/lib/payathon-test/phone-trial.sqlite`，只装载这一业务库。
- 服务端仅监听 `127.0.0.1:8088`；SSH 将本机 `127.0.0.1:18888` 转发过去，不增加 Nginx 公网管理入口。
- 已限制 Host、跨站写请求，密码会话为 HttpOnly／SameSite=Strict；进程不可访问短信配置、删除清单和旧测试库。
- 管理服务和 SSH 连接独立；关闭连接不停止上秤、备份或服务器管理服务。

服务器检查：

```sh
systemctl status payathon-database-admin.service --no-pager
journalctl -u payathon-database-admin.service -n 30 --no-pager
ss -ltn '( sport = :8088 )'
systemctl start payathon-backup.service
```

工具依赖版本保存在 `/opt/payathon-tools/database-admin/requirements.lock`。升级先在隔离示例库验证登录、查询、编辑及外键行为，再替换环境，不直接拿用户记录做增删改试验。
