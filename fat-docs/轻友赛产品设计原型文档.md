# 秤群结队产品需求文档

版本 0.5 · 2026 年 10 月 13 日 · 按当前静态页面逻辑更新

秤群结队是面向熟人小组的体重记录与数据分析产品。用户创建或加入小组，在开始前填写身高和起始体重、生成本期目标；房主确认开始后，成员记录每天的体重，查看成员个人趋势以及全组同图对比，到期后回顾本期记录。

当前范围聚焦组队、准备、当天记录、个人基础分析、小组数据对比和期末复盘。高级分析、付费、订单、AI、导出与自动通知不在本版范围。小组同图比较是当前基础能力，不是付费功能。

本文替代 v0.4 的当前需求口径，旧版见[归档](archive/轻友赛产品设计原型文档-v0.4.md)。视觉与逐页布局见[前端与视觉需求 v2.0](轻友赛前端与视觉需求.md)。本次只更新文档，不修改静态页面。

### 阅读口径

- **本版需求**：依据当前页面保留的流程和规则，用于后续实现。
- **静态实现**：当前浏览器内可表达或执行的逻辑，不代表已有真实账号、多人服务或权限系统。
- **未实现／待确认**：明确列出，不以旧版规划或内部场景函数充当已实现入口。

### 本版范围

| 项目 | 本版方案 |
| --- | --- |
| 用户 | 2–8 人熟人小组，无单人开始入口 |
| 创建周期 | 默认 14 天；预设 14／28／56；自定义 14–90 整数 |
| 小组名称 | 选填；未填写时采用「晚饭后散步小队」 |
| 准备 | 填身高、起始体重，按强度与天数生成目标；开始前可修改 |
| 开始条件 | 房主操作、至少 2 人、全员已准备 |
| 记录 | 手动输入当天体重，公斤／斤切换；覆盖当天记录先确认 |
| 成员分析 | 从头像或姓名进入，查看原始趋势、记录天数、覆盖率和明细 |
| 小组分析 | 所有成员同图，切换体重／体重变化／变化比例 |
| 导航 | 小组、记录、数据；没有独立分析或我的 Tab |
| 未更新 | 成员行展示状态；不提供自动提醒或房主提醒弹层 |
| 结束 | 记录概况、按覆盖率排列的成员参与情况、再组一期 |
| 暂不包含 | 付费、AI、导出、聊天、鼓励／倒赞、补录入口、账号设置 |

## 1 用户流程与基础平台

### 1.1 主流程

创建路径：首页 → 创建小组 → 确认小组信息 → 组队大厅 → 填写准备信息 → 房主确认开始 → 小组进行中。

加入路径：首页 → 输入邀请码 → 查看小组与参与规则 → 勾选同意 → 加入大厅 → 完成本人准备。

开始后：

- 「小组」查看截止时间、周期进度和成员状态，点击成员头像或姓名查看个人分析。
- 「记录」输入当天体重；保存成功回到小组。
- 「数据」查看全体成员的同图对比，不展示个人资料或账号设置。
- 已结束的小组展示本期复盘；「再组一期」进入新的创建流程。

当前没有登录注册页面，也没有高级功能预览、购买或解锁路径。

### 1.2 创建小组

| 字段 | 规则 |
| --- | --- |
| 名称 | 选填，最多 24 字符；去除首尾空白后为空时使用默认名 |
| 介绍 | 选填；无内容不在大厅保留空白占位 |
| 天数 | 默认 14；14、28、56 三个预设和第四项自定义输入；仅接受 14–90 整数 |
| 强度 | 低／中／高，默认低；高强度必须确认后选中 |

默认名是输入框占位提示，不是预填 value。用户可以直接输入其他名字，不必先删除默认文本。

自定义在第四项内直接编辑，不增加单独输入框。选择自定义时取消预设选中状态；用户输入过程中不弹非法提示，完成输入后的失焦或提交才校验。点击预设值时不因离开自定义输入而抢先弹错。

点击「创建」打开确认弹窗，核对最终名称、天数和强度；日期此时尚未确定。「确认创建」才建立待开始房间，「返回修改」保留表单。

### 1.3 房间与成员

创建成功时只有房主，状态为待开始。至少 2 人、所有当前成员都已准备，房主才能发起开始；其他成员显示等待房主开始。上限为 8 人，满员时邀请不可用。

邀请弹窗展示邀请码和复制按钮，不发送消息。加入详情须明确组内可见范围，以及开营后不能中途退出、房主不能提前关闭；同意勾选默认不选。

开始前提供返回／取消加入路径；当前静态页面仅进行本地导航，不等同于已完成服务端成员撤销。开始后不提供退出、踢人、提前关闭或修改他人数据入口。长时间未记录只改变显示状态，不自动移除成员。

中途加入者的加入日参与覆盖率计算，但当前加入入口只打开固定待开始示例，完整中途加入流程未实现。不得将其描述为已可用功能。

### 1.4 准备与目标

本人填写身高 cm 和起始体重 kg，校验范围分别为 80–250 cm、20–300 kg。输入不得预填用户真实信息，错误显示在对应字段。

点击「生成目标体重」成功后：

- 保存身高、起始体重与目标值。
- 本人准备状态切换为已准备，成员卡和准备卡同步。
- 准备卡展示目标、身高、起始体重及「修改身高体重」入口。

修改使用手机底部面板，保存有效数据后重新计算目标；取消保持原值，失败不先提交新值。修改仅在待开始状态开放。

目标在当前记录页只读，不允许直接输入目标值；不设置人工目标审核或公平性审核流程。静态算法为起始体重减去强度对应的日变化量乘以周期，日变化量为低 0.02、中 0.035、高 0.05 kg，结果下限为 1 kg。该算法只是当前占位实现，身高尚未参与计算，不作为正式目标算法或健康评估需求。

### 1.5 开始与日期

点击「开始本期」先展示起止日期和本期天数；确认前不改变房间状态。开始日取最终确认时的北京时间当天，结束日为开始日加 N−1 天，截止为结束日 23:59。

最终提交再次检查人数、角色、全员准备；条件变化则返回检查。跨北京时间零点时重新显示日期供确认。成功后房间进入进行中，当前成员加入日设为开始日，本期记录初始化。

开始按钮位于独立固定操作区，不随准备卡输入前后或结果高度变化而移动。

## 2 记录与数据分析

### 2.1 当天记录

每位成员每天最多保留一条主要记录。当前界面保存到本地状态 today，不提供日期选择、历史编辑或补录入口。

输入支持公斤／斤切换：1 kg = 2 斤，切换同步转换已填数字和目标显示，统一以 kg 保存、保留两位小数。0、负数、非有效数字拒绝保存。当前没有异常波动确认、私密备注或原始单位留存逻辑。

当天已有记录时先显示原记录与修改后值，由用户确认或取消；确认后替换同一天记录，不追加第二条。当前不保留修改历史版本。

保存成功后回到小组，概况、个人折线和小组对比使用同一份记录更新。待开始或已结束时不能新增记录。

### 2.2 小组概况

顶部展示小组名与邀请入口。时间卡展示截止日期、当天进度和剩余时间：

- 进行中：「第 X / N 天」「还有 N−X 天」。
- 最后一天：「今天结束」。
- 已结束：「已结束」。
- 起始日期之前：「尚未开始」。

进度是日序／总天数，限制在 0–100%，不是精确到小时的倒计时。

成员行展示头像、姓名、今日记录状态、迷你趋势、最新体重及相对首条变化。减少时显示「已减重 0.40 kg」，增加时显示「已增重 0.10 kg」；不足两条记录显示数据不足。最新读数不一定是今天，状态标签用于区分。

迷你曲线只展示，不可点击；头像或姓名进入个人分析。无鼓励、倒赞或聊天按钮。

### 2.3 成员个人分析

个人分析作为小组子页面，标题为「某某的数据分析」，返回小组；不设置成员选择框，也不占独立底部 Tab。

保留原始体重折线、近 7／28 天、记录天数、记录覆盖率和记录明细。默认近 28 天。移除重复趋势标题、首末变化卡、最低／最高卡、指标说明和高级预览。

点按原始记录点显示日期、体重，以及已有补录标志。记录明细通过整行入口打开独立面板，不在原页折叠展开；按日期倒序显示日期／状态／体重，底部关闭，不重复姓名、范围与条数说明。

### 2.4 小组数据

「数据」为小组整体分析页面。所有成员绘制在同一张图表内，用不同颜色及姓名对应，不限制为个人数据页，也不设置成员筛选器。

默认近 28 天、体重变化。可选近 7／28 天，以及体重／体重变化／变化比例。图表下方紧凑展示成员姓名、颜色和当前维度数值，随范围、维度同步更新。

不显示单独的记录参与进度卡，不添加高级功能、AI 或导出。

### 2.5 统一计算口径

| 指标 | 计算与展示规则 |
| --- | --- |
| 小组行变化 | 本期最新记录减本期首条；至少两条，否则数据不足；用已减重／已增重表达 |
| 个人记录天数 | 所选区间内的有效日期数；当前一天一条记录 |
| 个人覆盖率 | 有效日期数 ÷ 从区间起点与成员加入日中较晚者至当前日期的天数，含起止日；不计算未来日期 |
| 小组原始体重 | 每个可见日期对应的实际 kg 读数 |
| 小组体重变化 | 该日期读数减该成员本期首条读数 |
| 小组变化比例 | （该日期读数减本期首条读数）÷ 本期首条读数 × 100% |
| 小组成员数值区 | 当前可见区间最后一条记录的对应维度值；无记录为 — |
| 复盘覆盖率 | 本期有效记录日数 ÷ 成员加入日至本期结束日的天数 |

结束状态的分析锚点为截止日；进行中为当前状态日期。切换近 7／28 天不重置小组变化基准，基准始终是本期首条记录，不能误用准备时起始体重或区间首条替代。

变化图保留正负方向和单位，增加不应被渲染为减重。缺失日期不补零、不伪造观测点，实际点之间连线。单点可以显示原始点或相对自身首条的零变化，但不能据此作趋势判断。

当前不计算移动均值、脂肪减少、健康评分或减重效果结论。个人图表支持点按；小组图表目前只有 SVG title，没有手机点按详情动作。

## 3 版本范围与商业化

本版没有免费／高级两档分析，也没有收费商品、价格、权益或购买路径。现有组队、记录、个人基础分析和小组同图对比属于同一套基础流程。

v0.4 的高级分析、Vibe Pay 收款、有效期、退款及成本测算属于历史方案，已移至归档，不作为当前开发要求。若未来重新讨论商业化，应单独确认范围，不能因项目参加 PAYATHON 就恢复已删页面。

不做资金竞赛、承诺金、奖金分配、提现或视频核验。

## 4 状态、异常与交付边界

| 状态／事件 | 页面行为 |
| --- | --- |
| 人数不足 2 | 开始按钮禁用，显示至少 2 人的原因 |
| 有成员未准备 | 开始按钮禁用，显示还有 N 位成员未准备 |
| 非房主 | 等待房主开始，不允许发起 |
| 高强度取消 | 保留原强度及表单 |
| 天数非法 | 完成输入后提示，阻止创建 |
| 准备信息非法／生成失败 | 保持原状态，不提交无效结果 |
| 创建／开始确认取消 | 保留输入或准备，房间不提前进入下一状态 |
| 邀请失效／满员 | 禁止确认加入或邀请，显示原因 |
| 无记录 | 显示空态，不生成曲线结论；本人个人分析可引导去记录 |
| 单条记录 | 显示单点，小组概况变化为数据不足 |
| 今日重复保存 | 前后数值确认；确认才覆盖 |
| 连续未更新 | 显示多日未记录，不移除或暂停 |
| 本期已结束 | 展示复盘，记录页阻止新增 |

当前「多日未记录」按最新记录日（无记录则加入日／开始日）与 today−3 天比较，属于日期级状态，不是精确连续 72 小时计时。没有房主提醒弹层、24 小时重提醒或后台任务。

当前状态日期存于本地 state，不随真实时钟自动持续推进；已结束布局依赖房间状态切换。自动到期、结束后的服务端禁止加入及邀请失效尚需正式实现。

## 5 手机页面原型规格

视觉参数、颜色和弹层尺寸以配套视觉文档为准。本节定义页面职责。

| 页面 | 内容与主要动作 |
| --- | --- |
| P01 首页 | 产品名、创建小组、加入小组；无介绍堆叠或其他入口 |
| P02 创建 | 选填名称／介绍、天数、强度、固定创建按钮、创建确认 |
| P03 加入 | 邀请码、详情、参与规则、未预选同意勾选、确认加入 |
| P04 大厅 | 小组信息、成员与准备、本人准备／修改、固定开始按钮 |
| P05 小组 | 截止日期和时间进度、成员状态及最新读数、邀请、个人分析入口 |
| P06 记录 | 单位切换、大数字输入、只读目标、固定保存、覆盖确认 |
| P07 个人分析 | 单成员折线、时间范围、两项统计、记录明细面板 |
| P08 小组数据 | 全成员同图、时间范围、三个维度、紧凑成员数值 |
| P09 复盘 | 本期概况、按记录覆盖率排列的成员列表、再组一期 |

开始后底部导航固定为小组／记录／数据，个人分析属于小组。主要操作区独立固定，不能为固定按钮而撑高内容卡片。修改和长列表采用底部面板，内部滚动、底部操作可见。数字输入隐藏桌面微调箭头，输入过程不反复弹错。

产品页不放场景切换工具、原型说明块或预览控制。独立 mobile.html 的尺寸与页面选择仅用于开发预览。

## 6 数据对象与权限边界

### 6.1 当前静态数据对象

| 对象 | 当前字段／用途 |
| --- | --- |
| 页面状态 | page、today、role；当前页面、本地日期与角色 |
| 房间 | name、intro、days、intensity、status、start |
| 成员 | name、ready、height、weight、target、join；数组首位代表本人 |
| 记录 | date、weight、backfill；按成员索引保存，weight 为 kg |
| 创建草稿 | 名称、介绍、天数、强度及自定义输入状态 |
| 分析选择 | 个人所选成员／范围、小组维度／范围；属于界面状态 |

当前页面路由内部仍使用 me 表示「数据」，不能据此将产品职责改回「我的」。localStorage 键为 qingyou-v1，不是账号或真实用户身份。

### 6.2 正式实现需遵守的业务权限

- 成员只能新增或修改本人的有效日期记录，房主不能修改他人数据。
- 本期体重与趋势在小组成员间可见；邀请未加入者不能查看，其他小组无访问权。
- 至少 2 位不同用户且全员准备后才能开始，不能依靠重复加入凑人数。
- 开营前取消加入应真正撤销成员关系与访问权；不能只跳回首页。
- 开始后不提供普通退出、踢人或提前关闭；不得因此自动移除未更新成员。
- 到期后阻止新成员和新记录，原成员仍能查看本期历史。

这些是后续服务端需要执行的要求；当前静态页面没有身份鉴别或服务端访问控制，不能宣称已保障这些权限。数据删除、账号注销及支持流程当前没有产品入口，正式上线前应另行定义，不得以不可退出规则代替。

## 7 开发顺序与验收

### 7.1 后续实现顺序

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| 当前原型一致性 | 页面职责、口径、交互及文档保持一致 | 对照现有静态页面核对 |
| 真实组队与数据 | 身份、房间、真实邀请码、多人准备、本人记录与访问控制 | 两位不同用户完成创建／加入／准备／开始／记录 |
| 周期与分析 | 真实日期推进、自动到期、个人统计与小组对比 | 对照固定样本复算，结束状态前后一致 |
| 手机体验与试用 | 键盘、安全区、窄屏、长列表、真实熟人小组试用 | 实机验证和小组反馈 |

高级功能与支付不属于上述交付阶段。目标算法、完整中途加入和账号数据处理需另行确认后纳入具体迭代。

### 7.2 关键验收场景

- 名称不填采用默认名，输入自定义名称直接替换，不需要删除预填文本。
- 周期默认 14，预设和自定义互斥；14／90 可用，13／91／空值／小数不可提交；第一位数字不提前报错。
- 创建前核对名称、天数、强度；取消不丢表单。
- 高强度需要确认，取消保留原值。
- 准备成功才变为已准备；修改有效数据重算目标，取消保持原值。
- 1 人不能开始；2 人有任一未准备仍不能开始；全员准备后房主才可开始。
- 打开开始确认不启动，最终确认才确定起止日期；跨日需重新核对。
- 输入前后和准备状态变化不移动固定主要按钮，不出现人为撑高的准备卡。
- 70 kg 和 140 斤存为一致记录；覆盖当天值不重复计入，取消不覆盖。
- 成员趋势线不可跳转，头像／姓名进入对应个人分析。
- 个人范围、曲线、两项统计和明细使用一致数据；明细可打开关闭，不扩张原页面。
- 数据 Tab 显示全组，维度切换同时更新轴、单位、曲线和成员数值。
- 小组变化以本期首条为基准，切换范围不重置；晚加入成员覆盖率不计加入前日期。
- 无记录不补零；单点不编造趋势；小组成员无可见记录时数值为 —。
- 结束后不可新增记录，复盘同覆盖率并列，再组一期回到默认创建表单。
- 当前产品页不存在高级版、订单、AI、导出或内嵌预览工具入口。

### 7.3 当前验证范围与缺口

当前验证主要来自本地源代码及移动端浏览器预览，不代表服务端、真实手机或真实多人业务已验证。

已知静态占位：固定邀请码、示例昵称、固定加入详情与加入后 21 天示例；邀请未动态绑定用户新建房间；场景控制移除后新建单人房间不能通过真实远端好友补齐人数；没有实际自动到期或后台通知。

上述差异本次只记录，不修改前端，也不将它们写成已完成能力。
