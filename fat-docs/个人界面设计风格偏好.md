# 个人界面设计风格偏好

整理日期：2026-10-13；更新：2026-10-14
依据：本轮「上秤」移动端原型的多次修改与反馈。

本文用于后续页面设计、前端实现与设计评审。它记录的是用户在实际页面中表现出的偏好，不是通用设计规范。明确要求与归纳建议分别标注；未经讨论的部分不应据此扩大功能范围。

## 1. 风格核心

**清爽、克制、精致，以手机上的实际操作体验为先。**

用户追求的简洁不只是少放元素，还包括：少解释、少重复、少跳转、少打断，页面在操作前后保持稳定。必要的信息应直接可见，必要的动作应容易点击；视觉设计服务于理解和操作。

## 2. 视觉与布局

### 明确体现的偏好

- 字体与图标要对齐。装饰箭头如果影响居中或显得多余，可以直接去掉。
- 输入的数字应足够大、清晰、好看，尤其是体重、身高和天数。
- 卡片应紧凑、留白适度。不能为了固定按钮位置，把内容卡片撑得很高。
- 日期、修改前后数值等关键内容要有层次，避免把一长串文字居中塞进灰色方块。
- 时间范围切换按钮可以更扁，避免控件过厚、占据过多空间。
- 不需要的统计卡片应删除，不必为了填满页面而保留。

### 本轮接受的视觉方向

- 浅色背景、白色卡片、柔和边框与圆角。
- 珊瑚红作为主要操作色，浅红用于选中或辅助强调。
- 深色主文字、灰色次要文字，依靠字号与字重建立层级。
- 多成员图表使用不同颜色，曲线、图例和对应数值保持颜色一致。

以上是当前项目已接受的方向，不代表所有项目都必须使用红色或卡片布局。

### 分段选择框与动效（2026-10-14 用户确认并认可实现）

- 喜欢当前「公斤／斤」选择器的胶囊圆角程度；保留浅灰底、白色选中块与珊瑚红选中文字。
- 切换时选中块应在选项之间平滑滑动，带轻微拉伸、回弹和柔和收尾，避免直接闪换或重新出现。
- Apple 液态玻璃仅作为流畅动效参考，不采用其玻璃、透明、折射或模糊外观。
- 快速来回切换时从当前位置连续转向，不排队播放。尊重系统「减少动态效果」，此时即时切换。
- 已确认使用范围：记录页「公斤／斤」、数据页「近 7 天／近 28 天」「体重／体重变化／变化比例」，以及主导航「小组／记录／数据」。这几处统一胶囊圆角与同一套动效，不扩展为所有按钮。
- 手机主导航在三等分的胶囊轨道内水平滑动；桌面侧栏沿纵向滑动。切换页面时保留导航滑块，避免重新出现；固定导航高度与安全区留白不变。
- 筛选选中态立即响应，图表和数值随最新范围更新；快速切换时以最后一次选择为准，旧请求不得覆盖新结果。

## 3. 移动端操作

### 页面稳定

这是明确且优先级很高的要求。

- 页面底部主要按钮的位置应稳定，不能因输入前后、结果生成或卡片高度变化而上下移动。
- 固定操作区应独立于内容高度；不要靠增加卡片空白来维持按钮位置。
- 为固定按钮、底部导航和安全区域预留空间，避免遮挡内容。
- 表单错误、状态切换与结果展示应尽量减少布局跳动。

### 输入直接、过程不中断

- 「自定义」天数直接做成可输入的选项，不再弹出额外输入框。
- 预设值和自定义值互斥，选中状态只能有一个，不能留下多个对号。
- 不要在用户输入第一位数字时就报错。完成输入后再校验，例如失焦或提交时。
- 本项目天数范围为 14–90 天，预设为 14、28、56 天；这是业务配置，不是通用风格要求。
- 手机数字输入不显示桌面式上下微调箭头，并使用合适的数字键盘。
- 可选字段保持真正可选。默认小组名用占位提示，输入框实际为空；用户未填写时才采用默认名。
- 避免「留空使用：」等解释性前缀，让提示本身足够自然。

### 入口明确，减少误触

- 返回按钮采用适合手机的简洁样式，并提供足够点击面积。
- 列表入口整行可点，文字、数量、方向提示各有清晰位置。
- 纯展示的小趋势线不应可点击，避免误触跳转。
- 成员个人分析从成员头像或姓名进入，页面围绕该成员展开，不再放一排成员选择器。

## 4. 弹窗与底部面板

### 明确要求

- 创建小组前需要确认信息，帮助用户核对小组名、天数与难度。
- 修改身高体重的操作应符合移动端习惯。
- 记录明细通过入口打开独立面板，并能关闭；不要在原页面使用折叠卡片展开长列表。
- 有底部取消或关闭动作时，顶部叉号可以省略。
- 弹窗中间的日期、数值等信息需要认真排版，不能只有一个粗糙的灰色块。

### 本轮形成的实现建议

- 表单编辑和长明细优先使用底部面板；列表内部滚动，操作按钮保持可见。
- 简短确认可使用弹窗，信息顺序为标题、关键内容、主要动作、取消。
- 确认内容用结构表达：日期分起止，修改值分前后，避免冗长句子。
- 提交后才更新数据，取消应保留原状态。

## 5. 文案：只留下有用的话

用户反复要求删除说明性、重复性文案，应默认克制。

### 已明确删掉的类型

- 「演示目标」等面向原型或实现的说明。
- 「开营后目标锁定。」等占据单独区域的说明。
- 「保存后将根据新数据更新本期目标体重。」等可由操作结果体现的解释。
- 「指标说明」及其展开内容。
- 已有页面标题时，再重复「某某的记录趋势」。
- 明细弹窗中的「姓名 · 近 28 天 · 共 2 条」等重复信息。
- 页面内的预览工具及场景操作控件。
- 邀请弹窗中额外的「加入前不会展示成员体重。」提示框。

### 命名偏好

- 按钮直接说动作，例如「创建」，不写「创建并进入组队大厅」。
- 数值标签使用直观、面向用户的表达，例如「已减重 0.40 kg」。
- 文案应准确：体重增加时显示「已增重」，不能仅取绝对值后统一叫减重。
- 只删除表达，不应由此擅自改变权限、数据规则或必要的业务校验。

## 6. 数据展示与导航

### 当前已明确的页面职责

| 入口 | 内容 |
| --- | --- |
| 小组 | 成员概况、截止日期、时间进度 |
| 记录 | 录入与修改个人体重记录 |
| 数据 | 小组所有成员的整体对比分析 |
| 成员头像或姓名 | 该成员的个人分析 |

「数据」不是「我的数据」，不能改成个人资料或账号设置页。

### 展示偏好

- 小组成员放在同一张图中，用不同颜色对比。
- 支持从不同维度看数据，而不是堆叠很多独立统计卡片。
- 当前保留体重、体重变化、变化比例三个维度，以及近 7 天、近 28 天范围。
- 保留基础分析，避免未经请求重新加入付费、AI 或其他高级功能。
- 「记录参与」独立卡片被认为没有必要，已删除。
- 图表下方用紧凑的成员数值区承接图例，数值随当前维度切换；这是本轮采用的替代方案，后续仍可调整。
- 小组截止日期搭配进度条，直观表达距结束还有多久。

## 7. 后续设计的默认判断顺序

以下为根据本轮反馈归纳的建议：

1. 先明确页面要完成的任务，再决定放什么内容。
2. 优先确保手机操作顺畅、按钮稳定、输入不中断。
3. 合并重复信息，删除没有明确用途的说明、卡片和入口。
4. 用排版、分组和颜色表达关系，少靠解释文字。
5. 再打磨圆角、间距、字号和控件厚度。
6. 在真实页面检查输入前后、状态切换和弹窗打开后的效果。

## 8. 交付前快速检查

- 主要按钮会不会因为输入或状态变化而移动？
- 是否为了撑布局而出现大片无意义空白？
- 是否出现桌面式数字微调箭头或不适合手机的返回入口？
- 是否在输入尚未完成时就弹出错误？
- 选中状态是否唯一且准确？
- 是否有重复标题、实现说明或可以删除的解释句？
- 卡片是否确实承担独立任务，还是仅仅把内容装进了框？
- 展示元素是否意外可点，造成误触？
- 页面职责是否准确，尤其是否把小组数据误做成个人数据？
- 图表颜色、数值、时间范围和维度是否一致？
