# 上秤产品需求文档

版本 0.14 · 2026 年 10 月 14 日 · 首页与记录确认交互更新

本文定义年满 18 岁用户的熟人小组体重记录业务：组队、准备、当天记录、个人趋势、全组同图与期末复盘。当前不设付费门槛；收费范围按[总控第 6–7 节](../项目总控文档.md)后续评估，不预先承诺永久免费。

正式代码在 `apps/`，`prototype/` 为保留的静态参考。当前状态及证据见[开发交接](../docs/开发交接.md)和[开发记录](../docs/本地基础版开发记录.md)，外观见[视觉规范](上秤前端与视觉需求.md)。本文只写现行业务规则；历史原型差异见[任务清单第 2 节](../docs/开发任务清单.md)，未确认事项不作为要求。

## 1 用户流程与基础平台

### 1.1 主流程

创建路径：首页 → 创建小组 → 确认小组信息 → 组队大厅 → 填写准备信息 → 确认开始 → 小组进行中。由当前开始权限持有人发起。

开营前加入：首页 → 输入邀请码 → 查看小组与规则 → 同意并加入 → 大厅完成准备。

中途加入：首页 → 邀请详情与剩余天数检查 → 同意并填写准备信息 → 服务端重新检查资格并提交加入 → 进行中小组。未提交表单不占名额；成功提交日作为加入日。目标使用同一公式，参与天数取有效提交时含加入当天的剩余天数。

开始后：

- 「小组」查看截止时间、周期进度和成员状态，点击成员头像或姓名查看个人分析。
- 「记录」输入当天体重；保存成功回到小组。
- 「数据」查看全体成员的同图对比，不展示个人资料或账号设置。
- 已结束的小组展示本期复盘；「再组一期」进入新的创建流程。

登录后回到正在创建／加入的流程；首次使用通过未预选的「我已年满 18 岁」声明确认，未确认不可创建、加入或提交身体数据，服务端同样校验。不收集身份证或完整生日。一个账号同时最多参加一个未结束小组，创建也计入。

### 1.2 创建小组

| 字段 | 规则 |
| --- | --- |
| 名称 | 选填，最多 24 字符；去除首尾空白后为空时使用「晚饭后散步小队」 |
| 介绍 | 选填；无内容不在大厅保留空白占位 |
| 天数 | 默认 14；14、28、56 三个预设和第四项自定义输入；仅接受 14–90 整数 |
| 强度 | 低／中／高／极高，默认低；28 天基准比例分别为 2%／3%／4%／5%；仅极高须确认后选中 |

默认名是输入框占位提示，不是预填 value。用户可以直接输入其他名字，不必先删除默认文本。

自定义在第四项内直接编辑，不增加单独输入框。选择自定义时取消预设选中状态；用户输入过程中不弹非法提示，完成输入后的失焦或提交才校验。点击预设值时不因离开自定义输入而抢先弹错。

点击「创建」打开确认弹窗，核对最终名称、天数和强度；日期此时尚未确定。「确认创建」才建立待开始房间，「返回修改」保留表单。创建确认不等于正式开始：组队阶段仍可修改名称、介绍和周期，最终确认开始成功后才锁定。编辑仅限当前开始权限持有人；改周期保留身高体重，取消全员准备，每位成员重新确认新目标，不得静默替换已接受的任务。

### 1.3 房间、成员与退出

创建成功时只有创建者，房间待开始。至少 2 位不同用户且全员准备后，当前开始权限持有人才可确认开始；其他成员等待。开始权限初始由创建者持有，接替者权限相同；开始前编辑小组名称、介绍和周期的权限随开始权限一并交接，不因此获得踢人、改他人体重或替全组提前结束的权限。

组队阶段所有成员均可退出；服务端真正撤销成员关系、停止本组数据访问、不再计入人数和全员准备条件，并释放该账号的小组名额。当前开始权限持有人退出时，小组继续，由最早加入的在组成员接替；后续持有人退出按同样规则交接，原持有人重新加入不会自动取回权限；交接与退出在同一事务中完成。最后一人退出则自动关闭空组、使邀请失效；退出后再次加入须重新填写准备信息，不恢复旧的已准备状态，按本次成功加入时间重新排序。已关闭的房间需重新创建，不能再加入。

开营后不提供普通退出、踢人、提前关闭功能，也不因未记录自动移除成员。数据删除和注销可通过对应入口或支持流程处理，不受此限制。2026-10-14 用户决定不设计独立撤回共享功能。

最多 8 人。所有在组成员均可发起邀请；邀请码不另设固定过期天数，空组关闭、结束或进行中剩余不足 14 天时禁止加入。满员只是暂停加入，组队阶段有人退出释放名额后原邀请码可继续使用。邀请弹窗展示邀请码与复制按钮，不替用户发送消息。加入详情明确本期全部体重、目标与趋势在组内可见，包含新成员加入前的日期；同意勾选默认不选，未加入者不可查看身体数据。

中途加入按北京时间、包含当天计算剩余天数，至少 14 天可加入，13 天及以下不可。例：10 月 28 日结束，10 月 15 日可加入，10 月 16 日不可。最终提交检查邀请、名额、当前小组、准备信息和最新日期；跨日后不再满足条件则保留输入并说明无法加入，不静默提交。

加入不改变本期日期，不清空已有记录，不让既有成员重新准备。成功加入后可看本期全部体重、目标及趋势，覆盖率只从本人加入日计算。

### 1.4 准备与目标

本人填写身高 cm 和起始体重 kg；当前技术校验分别为 80–250 cm、20–300 kg，正式范围按总控 4.5 冻结。输入不得预填用户真实信息，错误显示在对应字段。

目标公式、四档比例、BMI 修正及时间插值统一见[总控 4.4](../项目总控文档.md)，算法论证与样例见[研究稿](目标算法研究与建议.md)。保留当前算法，起始／目标低 BMI 不增加门槛或截断；目标用于组内挑战，不承诺个体效果或难度等价。

本人修改身高或起始体重后重算，服务端保存权威结果及算法版本；正式开始锁定输入、目标与版本，升级不静默改变进行中目标。当前实现与数学样例的证据见开发记录，不代表个体效果或难度等价已经验证。

准备有效提交才变为已准备；成员卡和准备卡同步。起始体重与目标组内可见；身高只作为目标计算输入，在填写或修改表单中使用，不在准备结果、成员资料、分析或共享字段中展示。身高持久保存必要性与期限仍待明确。

开营前可通过手机底部面板修改准备信息，取消或校验失败保留原值；中途加入者在有效加入前填写，提交后不提供修改起始信息的普通入口。准备结果显示目标与起始体重，目标只读。

### 1.5 开始与日期

点击「开始本期」先核对最新小组名称、介绍、周期及起止日期；打开弹窗不改变状态、不提前锁定小组。最终确认成功后锁定名称、介绍和周期。开始日取最终确认时的北京时间当天，结束日为开始日加 N−1 天，截止为结束日 23:59。

最终提交再次检查人数、当前开始权限、全员准备；成员或小组信息发生变化则刷新信息、重新确认，不能按旧周期开始。跨北京时间零点时重新显示日期供确认。成功后房间进入进行中，当前成员加入日设为开始日，本期记录初始化。

开始按钮位于独立固定操作区，不随准备卡输入前后或结果高度变化而移动。

### 1.6 登录、历史与待确认项

用户已确认手机号验证码优先；真实短信供应商仍需技术评估。本地适配器在登录页明确显示未发送短信的测试验证码。基础版不做专门换机找回、人工恢复或账号合并。同一凭据正常登录可读取服务端数据，未来收费的订单访问另行设计。

首页根据服务端当前未结束小组状态展示：已有待开始或进行中小组，只保留一个「返回当前小组」大按钮，不显示创建／加入大按钮；没有未结束小组（含只有结束历史）时显示「创建小组」「加入小组」。历史小组、账号与支持、隐私等次级入口仍可点击。历史按期次和日期区分，可进入只读复盘和成员分析，不依赖本地原型状态。

输入正式范围、身高保存及其他数据策略等未决事项见[总控 4.5](../项目总控文档.md)。正式手机号登录与数据控制的实施顺序、外部依赖和候选规则集中在[真实试用推进方案](../docs/真实试用推进方案.md)；测试身份和合成记录不自动迁入正式账号。

## 2 记录与数据分析

### 2.1 当天记录

每位成员每天最多一条记录，以服务端北京时间业务日为准；不提供日期选择、历史编辑或补录。

输入支持公斤／斤切换：1 kg = 2 斤，同步转换数字和目标，统一以 kg 校验、一次舍入保存两位。切换单位只改变显示，不保存或反复舍入内部值；正式输入上下限按总控 4.5 冻结。

当天已有记录时弹出「修改今日记录」，对照旧值与新值，确认才覆盖，取消保留输入且不写库；布局与颜色统一见视觉规范 D05。多设备版本冲突展示最新值并重新确认，不另做面向用户的修改历史列表。

本地正式应用异常恢复：连接失败、响应内容丢失或服务端 5xx 导致结果未知时，保留当次输入、日期、版本和请求编号；输入暂只读，主按钮改为「核对保存结果」，由用户显式重试原请求，同组导航往返仍保留待核对状态。已确认保存成功、仅后续同步失败时，明确显示「记录已保存，数据同步暂时中断」。跨日与覆盖冲突保留输入，更新权威日期／版本后要求再次提交或确认；不自动保存到次日。此状态仅保留在当前页面内存，不提供离线缓存、刷新恢复草稿或离线自动提交。

保存成功后回到小组，概况、个人折线和小组对比使用同一份记录更新。待开始或已结束时不能新增记录。

### 2.2 小组概况

顶部展示小组名与邀请入口。时间卡展示截止日期、当天进度和剩余时间：

- 进行中：「第 X / N 天」「还有 N−X 天」。
- 最后一天：「今天结束」。
- 已结束：「已结束」。
- 起始日期之前：「尚未开始」。

进度是日序／总天数，限制在 0–100%，不是精确到小时的倒计时。

成员行展示头像、姓名、今日记录状态、迷你趋势、最新体重及相对首条变化；成员目标也须有可达查看位置，具体放在成员行还是个人分析页在视觉同步时确定，不额外增加图表维度。减少时显示「已减重 0.40 kg」，增加时显示「已增重 0.10 kg」；不足两条记录显示数据不足。最新读数不一定是今天，状态标签用于区分。

迷你曲线只展示，不可点击；头像或姓名进入个人分析。无鼓励、倒赞或聊天按钮。

### 2.3 成员个人分析

个人分析作为小组子页面，标题为「某某的数据分析」，返回小组；不设置成员选择框，也不占独立底部 Tab。

保留原始体重折线、近 7／28 天、记录天数、记录覆盖率和记录明细。默认近 28 天。移除重复趋势标题、首末变化卡、最低／最高卡、指标说明和高级预览。

点按原始记录点显示日期、体重，以及已有补录标志。记录明细通过整行入口打开独立面板，不在原页折叠展开；按日期倒序显示日期／状态／体重，底部关闭，不重复姓名、范围与条数说明。

### 2.4 小组数据

「数据」为小组整体分析页面。所有成员绘制在同一张图表内，用不同颜色及姓名对应，不限制为个人数据页，也不设置成员筛选器。

默认近 28 天、体重变化。可选近 7／28 天，以及体重／体重变化／变化比例。图表下方紧凑展示成员姓名、颜色和当前维度数值，随范围、维度同步更新。

不显示单独的记录参与进度卡，不添加高级功能、AI 或导出。

### 2.5 统一计算口径

| 指标 | 计算与展示规则 |
| --- | --- |
| 小组行变化 | 本期最新记录减本期首条；至少两条，否则数据不足；用已减重／已增重表达 |
| 个人记录天数 | 所选区间内的有效日期数；当前一天一条记录 |
| 个人覆盖率 | 区间内有效日期数 ÷ 从区间起点、本期开始日、本人加入日的最晚者至分析锚点的天数，含起止日；锚点不晚于结束日，无有效天数为 — |
| 小组原始体重 | 每个可见日期对应的实际 kg 读数 |
| 小组体重变化 | 该日期读数减该成员本期首条读数 |
| 小组变化比例 | （该日期读数减本期首条读数）÷ 本期首条读数 × 100% |
| 小组成员数值区 | 当前可见区间最后一条记录的对应维度值；无记录为 — |
| 复盘覆盖率 | 本期有效记录日数 ÷ 成员有效参与天数；组队阶段退出者不纳入；按未舍入比率比较并列，稳定次序用加入顺序等非健康指标 |

结束状态的分析锚点为截止日；进行中为服务端当天。切换近 7／28 天不重置小组变化基准，基准始终是本期首条记录，不能误用准备时起始体重或区间首条替代。

变化图保留正负方向和单位，增加不应被渲染为减重。缺失日期不补零、不伪造观测点，实际点之间连线。单点可以显示原始点或相对自身首条的零变化，但不能据此作趋势判断。

当前不计算移动均值、脂肪减少、健康评分或减重效果结论。图表交互见视觉规范；服务端输出规范统计，数据更正／删除后重算统计、排名与缓存。

## 3 版本范围与商业化

本版没有免费／高级两档分析，也没有收费商品、价格、权益或购买路径。现有组队、记录、个人基础分析和小组同图对比属于同一套基础流程。

基础完成后再评估收费；商品、价格、支付接入与售后统一见总控第 6–7 节，不因参赛恢复旧商品方案。

不做资金竞赛、承诺金、奖金分配、提现或视频核验。

## 4 状态、异常与交付边界

| 状态／事件 | 页面行为 |
| --- | --- |
| 人数不足 2 | 开始按钮禁用，显示至少 2 人的原因 |
| 有成员未准备 | 开始按钮禁用，显示还有 N 位成员未准备 |
| 非当前开始权限持有人 | 等待持有人确认开始，不允许代发起 |
| 高／极高强度取消 | 保留原强度及表单 |
| 天数非法 | 完成输入后提示，阻止创建 |
| 准备信息非法／生成失败 | 保持原状态，不提交无效结果 |
| 创建／开始确认取消 | 保留输入或准备，房间不提前进入下一状态 |
| 邀请失效／满员／剩余不足 14 天 | 禁止加入，显示具体原因 |
| 组队阶段退出 | 撤销成员关系并释放名额；必要时交接开始权限 |
| 进行中退出请求 | 无普通入口；服务端拒绝，独立隐私支持仍可受理 |
| 无记录 | 显示空态，不生成曲线结论；本人个人分析可引导去记录 |
| 单条记录 | 显示单点，小组概况变化为数据不足 |
| 今日重复保存 | 前后数值确认；确认才覆盖 |
| 连续未更新 | 状态标签保留；正式版另向所有人提示，每轮最多两次，不自动移除 |
| 本期已结束 | 展示复盘，记录页阻止新增 |

日期、到期、记录异常恢复和接口处理按当前规则及 [API 契约](../docs/API契约.md)执行；静态原型的占位行为不代表正式应用状态。

### 4.1 未更新站内提示

- 连续 3 天未更新，提示一次；第 4 天再提示一次；同一轮最多两次，之后停止。
- 打开小组时站内提示所有当前成员，包括未更新本人；不做短信、邮件或手机系统推送。
- 每名接收人在北京时间同一天，不重复看到关于同一未更新成员的提示；刷新、重复任务、换设备不能绕过去重。
- 更新体重后结束旧轮；以后再次长时间未更新可开启新轮。修改旧提示或刷新页面不重置轮次。
- 日期按北京时间计算；有记录时以最新有效记录日为基准，无记录时以开始日与加入日中较晚者为基准。最后记录为 10 月 1 日时，10 月 4／5 日分别对应第 3／4 天；不用精确 72 小时计时。
- 错过提醒当天，后来打开时只显示关于同一成员当前轮次最新一条尚有效、尚未展示的提示；不堆积旧提示，不生成额外轮次，刷新不重弹。
- 对方已更新体重或本期已结束，旧提示作废，不再补弹。服务端保存轮次与展示回执，不能只靠本地存储实现。

当前实现和验证证据见开发记录；原型仅保留状态标签，不用于验收服务端去重。

## 5 手机页面原型规格

视觉参数、颜色和弹层尺寸以配套视觉文档为准。本节定义页面职责。

| 页面 | 内容与主要动作 |
| --- | --- |

## 6 数据对象与权限边界

### 6.1 当前静态数据对象

| 对象 | 当前字段／用途 |
| --- | --- |
| 页面状态 | page、today、role；当前页面、本地日期与角色 |
| 房间 | name、intro、days、intensity、status、start |
| 成员 | name、ready、height、weight、target、join；数组首位代表本人 |
| 记录 | date、weight、backfill；按成员索引保存，weight 为 kg |
| 创建草稿 | 名称、介绍、天数、强度及自定义输入状态 |
| 分析选择 | 个人所选成员／范围、小组维度／范围；属于界面状态 |

当前页面路由内部仍使用 me 表示「数据」，不能据此将产品职责改回「我的」。localStorage 键为 qingyou-v1，不是账号或真实用户身份。

### 6.2 正式实现需遵守的业务权限

- 成员只能新增或修改本人的当天记录，开始权限持有人同样不能修改他人数据。
- 本期体重、目标与趋势在小组成员间可见；身高仅作目标计算输入，不作数据展示；邀请未加入者不能查看，其他小组无访问权。
- 至少 2 位不同用户且全员准备后才能开始，不能依靠重复加入凑人数。
- 仅组队阶段所有人可退出；服务端撤销有效成员关系及访问权、释放名额，必要时交接开始权限；开营后不提供普通退出。
- 开始前编辑小组信息仅限当前开始权限持有人，交接后同步切换编辑权限；开始后所有人均不可修改小组名称、介绍和周期。
- 不提供踢人或替全组提前关闭的隐含权限；不得自动移除未更新成员。
- 到期后阻止新成员和新记录，原成员仍能查看本期历史。

权限由服务端验证；当前实现证据见开发记录。本人导出、注销在线删除和支持请求已有，保存策略／备份删除按[真实试用推进方案](../docs/真实试用推进方案.md)继续完善；不新增独立撤回共享功能，不得以不可普通退出拒绝数据删除或注销请求。
